# 界面改动审查

先跑一次机器检查，再人工看机器看不见的部分。

## 一、机器检查（先跑）

```bash
node tools/check-ui.mjs <改动的文件或目录>
```

退出码：0 干净 / 1 有指摘 / 2 用法错。某一行确实需要那个写法，就在该行加注释
`check-ui-ignore` 豁免 —— 但要能说出为什么。

它抓 18 类「一眼就是 AI 拼的」写法，按类别分：

| 类别 | 例子 |
| --- | --- |
| 装饰过度 | 卡片单边粗色条、彩色发光阴影、文字渐变、紫粉艳渐变 |
| 动效过度 | `transition: all`、悬停放大、`animate-pulse` 常驻循环 |
| 排版过度 | 字重 800+、全大写拉字距、斜体（中文字体只是被机械倾斜） |
| 文案空洞 | 堆功效形容词（极致/无缝/一站式）、填空白态的寒暄、感叹号 |
| 交互错配 | 悬停才开的菜单（触屏点不出）、标了 kbd 快捷键（当人面用不了） |
| 平台细节 | 输入框字号 <16px（iOS Safari 会放大整页）、间距不在 4px 栅格上 |

这套规则移植自 [minorun365/unslop-ai-app](https://github.com/minorun365/unslop-ai-app)
（Apache-2.0），规则逻辑原样保留。

## 二、人工检查（机器看不见的）

1. **状态齐全** —— 加载中 / 空 / 出错 / 部分失败，四个都要有，不能只有成功态
2. **可访问性** —— 键盘可达、焦点可见、图片有替代文本、颜色不是唯一信息载体
3. **边界** —— 超长文本截断还是换行？数量为 0 或 1000 时什么样？
4. **响应式** —— 最窄断点下会不会撑破
5. **信息减法** —— 这个元素不加会怎样？答不出「会少什么信息」就删掉

## 输出

按严重程度排，每条给 `文件:行号` 和一句修法。没有问题的类别写「无」。
机器检查的结果不用逐条转述 —— 直接贴它的输出。
