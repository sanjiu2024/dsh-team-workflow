# REQ-015 · 小队补全（成本 / 持久化 / 续聊 / 直投 / 重试超时 / 面板 / 成员工具）

- **状态**：进行中
- **对应版本**：`1.20.1 → 1.21.0`（加能力 → minor）
- **提出**：用户 2026-10-16：「你把小队功能完善一下吧，功能还有太多没有」。随后从
  REQ-009 §3 / REQ-010 §3 / REQ-011 §7 三份文档的「不做什么 + 天花板」里列出 9 个候选，
  用户勾选 7 项（**不做**审批通道、**不做**成员嵌套），并选「一次全做完」。

## 1. 要做什么

用户视角：「小队能用，但缺得太多。」具体补这 7 样 ——

1. **成本/token 看得见**：每个成员、每支小队花了多少 token。现在只有一个塞进 note 的文本行
   （`usageLine`），面板看不到、工具也问不出合计。
2. **重启后小队还在**：现在小队/黑板/转录全在进程内存里，dsh 一重启就没了 —— 用户这次就撞上过
   （「没有小队『昨天token账单』」）。要能捡起来接着干。
3. **能给跑完的成员续话**：现在只有「重派同名 = 重跑」（还会清空转录），不能给一个已经收工的成员
   追加一句「再把 X 查一下」。
4. **成员之间能直接说话**：现在只能靠黑板。REQ-009 §3 当年卡在「缺一个 `createUserMessage` 产物」，
   那个产物在 REQ-011 之后已经有了。
5. **失败能重试、能超时**：现在成员一失败就是「卡住」；也**没有任何墙钟上限**（只有 `maxSteps`）。
6. **面板补齐**：成员耗时、token 列、搜索框。（转录查看已经有 —— 侦察纠正过我一次。）
7. **成员工具集扩一点**：`web_search` / `web_fetch` / `worktree_new` / `worktree_list` / `say`。
   现在成员只有 read/write/edit/grep/glob/bash/board。

## 2. 为什么（不做的后果）

- **成本不可见** = 无法回答「这支小队值不值」。用户天天看 token 账单（本会话就拉过），小队是
  最烧 token 的功能，却唯独它没有结构化用量。
- **不持久化** = 一次重启丢掉全部在跑的工作，且**无法恢复**（转录也没了）。这是用户实际踩到的。
- **不能续话** = 每次追加要求都要重跑一个成员（冷启动 + 重新读文件），贵且会重复劳动。
- **不能直投** = 所有协调必须经过主 agent 转述到黑板，主 agent 成了瓶颈，且黑板是广播不是对话。
- **不重试/不超时** = 无人值守时会静默卡死或永远跑下去（`maxSteps` 只数步数，一个卡住的工具
  调用不算步）。
- **成员没有联网工具** = 只能靠 `bash` 里的 `curl` 硬打，绕过宿主的 SSRF 防护与大小上限。

## 3. 不做什么

- **不做成员审批通道**（用户没勾）。理由不变：宿主审批只有会话绑定的
  `ApprovalService.request`（`dsh-user-approval/lib/index.js:128-130`，无开着的 turn 直接 throw），
  成员不是会话 ⇒ 要自建问答通道，成本远高于收益。
- **不做成员嵌套**（用户没勾）：成员不能派成员。
- **不给成员 `worktree_merge` / `worktree_drop`**：合并回主分支与丢弃永远由主 agent 决定
  （REQ-001 的规矩）。成员只能建、只能看。
- **不改面板的只读约定**：一个写路由都不加（沿用 REQ-009 §6.2 / REQ-010 §3）。
- **不改授权模型的所有者语义以外的东西**：`authorize` 这次只放宽「同一工作目录的会话也算所有者」
  （持久化捡回必须如此），其余不变（收队后只读、空队名拒绝）。
- **不做成本（钱）**：仍无定价数据（REQ-010 §6 已证）。只做 token。
- **不做跨机器的状态同步**：落盘是本机的 `<DSH_HOME>`；两台机器各存各的。
- **不做「多个进程同时写同一工作目录」的并发保护**：同一工作目录被两个 dsh 进程同时打开时，
  落盘是**最后写入者赢**（§7 记明）。

## 6. 方案

### 6.1 状态形状（`lib/squad.js`）

新增字段（都要能过 `snapshot` 与落盘裁剪）：

| 位置 | 新字段 | 说明 |
| --- | --- | --- |
| squad | `cwd` | 建队时的工作目录。持久化捡回靠它，不靠会话 id |
| squad | `usage`（只读计算） | 小队合计 = 各成员 `usage` 之和，不落盘、不快照成字段（避免两份真相） |
| member | `usage` | 结构化 6 字段（in/out/total/cacheRead/cacheWrite/reasoning） |
| member | `startedAt` / `endedAt` / `durationMs` | 耗时（面板与工具都用） |
| member | `attempts` | 跑过几次（重试计数） |
| member | `inbox` | 待投消息队列（**不落盘**：重启后队列没有意义） |
| member | `history` | 上次的消息数组引用（**不落盘**：太大，重启后靠「原任务+结论」兜底） |

### 6.2 持久化（新文件 `lib/squad-store.js`）

- 位置：`<DSH_HOME>/team-workflow/squads/<wsKey>.json`；`wsKey` = 目录名净化 + `sha1(cwd).slice(0,8)`
  （纯函数 `workspaceKey(cwd)`，可单测）。
- 写入：tmp + rename 整体重写，**串行队列 + 750ms 防抖**（黑板/转录写得频繁，不防抖会反复写
  几 MB）；`dispose()` 与 `session/disposed` 时 flush。
- 读入：坏文件 → 改名 `.broken-<ts>` + warn + 从空开始（不抛错、不猜）。
- 版本：`{version: 1, cwd, squads: [...]}`；`version` 不认识 → 同样 quarantine。
- 落盘裁剪：转录每条 ≤1000 字符、每成员 ≤100 条（内存上限仍是 200×8000）；剔除
  `running` / `promise` / `abort` / `inbox` / `history`。
- **捡回 = 接管**：`load` 时若 `squad.owner !== 当前会话`，把它标 `adoptedFrom = owner` 并把
  `owner` 改成当前会话，然后放进**当前会话名下**的那张表。为什么这么做：新会话 id 一定不同，
  不改持有者就永远写不进（读得到、动不了）；接管之后 **`authorize` 一个字都不用改**（仍是
  「所有者才能写」），少一处可能写错的地方。同一工作目录 = 同一份工作。
- **落盘时机**：`persistSquad` 在每次状态变更后调用（建队/派成员/改行/写黑板/收口/续聊/直投），
  由 store 做 750ms 防抖；入队时**同步取快照并压好**（不是等写的时候再读状态）——
  否则「flush → 清状态 → 写」这条关停路径会写出一份空文件（自检逮到过 `squads: []`）。

### 6.3 续聊与直投（都要改循环）

- `runMemberLoop` 增两个入参：`messages`（可选种子历史）与 `takeInbox`（每步边界取待投消息）。
  注入点选在**上一步的工具结果全部追加完之后**，保证窗口不以 tool 消息开头（REQ-011 §4 的协议约束）。
- 新工具 `squad_send(squad, member, text)`：在跑 → 拒绝；否则以 `member.history`（或
  「原任务 + 上次结论」兜底）续跑。
- 新工具 `squad_say(squad, to, text)` + 成员工具 `say(to, text)`：在跑 → 进 `inbox`；不在跑 → 留队；
  两种都写目标转录 + 一条黑板（作者 = 发送者）。

### 6.4 重试与超时（`lib/squad-loop.js` + `lib/squad.js`）

- 配置：`retries`（默认 1）、`memberTimeoutMinutes`（默认 20），都进 `team/extensions/squad.json`
  与 `SQUAD_FIELDS`。
- **只对基础设施失败重试**（流抛错 / `finish.kind === "error"`）：带历史 + 一句「上次因 X 中断，请继续」。
  **`maxSteps` 耗尽不重试** —— 那是真循环，重试等于继续烧钱。
- 超时：`setTimeout` → `abort()`，note 写「超过 N 分钟上限」，状态「卡住」。

### 6.5 成员工具（`lib/squad-tools.js` 三处 + `lib/squad.js` 白名单）

新增：`web_search`、`web_fetch`（走 `ctx.web.search/fetch`）、`worktree_new`、`worktree_list`
（走 `lib/worktree.js` 的纯函数，`cwd` 取成员根）、`say`。**不加** `worktree_merge` / `worktree_drop`。

### 6.6 面板（`lib/client.js`）

成员行加耗时/token/尝试次数；小队卡加合计 token；顶部搜索框（纯客户端过滤，沿用 REQ-010 §6 的思路）。
**不加写路由。**

### 6.7 自检

`scripts/selftest-squad.mjs` 逐条加断言（§4 每一条都对应至少一个 `check`），并加 8 条反向实验的
**手动执行记录**（主会话做，见 REQ-013 §8 的事故）。

## 7. 天花板（做完之后仍不支持的）

- **不做审批通道**、**不做成员嵌套**（§3）。
- **同一工作目录被两个 dsh 进程同时打开时，落盘是最后写入者赢**：没有跨进程锁，也没有冲突检测。
  要避免就一个工作目录只开一个 dsh。
- **转录落盘会被压缩**（≤100 条 × 1000 字符）：重启后能看到摘要级转录，**不是**完整原文。
- **`inbox` 与 `history` 不落盘**：重启后未投的消息与消息历史丢失（续聊退化为「原任务+结论」）。
- **小队仍是「本机」状态**：两台机器各存各的，不互相同步。
- **成员仍没有审批**：遇到需要确认的操作只能自己判断或写进结论。
- **成员的 `bash` 隔离强度 = 宿主此刻的沙箱策略**（2026-10-16 补，原文只说「边界不变」，没说机制）：
  成员的 bash 走宿主 shell 服务，策略由 `policyFor(member.worktree)` 取**宿主当前策略**、只把
  `workspaceRoot` 钉到该成员的 worktree。所以 `danger-full-access` 下成员照样能写到 worktree 外面 ——
  **worktree 是「默认落点」，不是「边界」**。fs 工具（read/write/edit/glob/grep）才是真边界
  （`resolveInside`，越界直接拒，且挡了符号链接）。要收窄就给该队 `bash: false`
  （REQ-016 的 A4 会加按角色的工具白名单）。
- **成本（钱）仍无**：只有 token。

### 反向实验（主会话自己做；改坏 → 必须变红 → 还原）

「反向实验没红」本身就是一次假绿。

### 实现期间自己踩到并修掉的三处

1. **循环 TDZ**：`finish()` 在 `let messages` 之前就被早退路径调用 → `Cannot access 'messages'
   before initialization`（既有自检当场变红）。把声明提到 `finish` 之前。
2. **关停时丢写**：`store.dispose()` 先 `flush()` 再置 `disposed`，而写是排队的 → 排队那次写
   被 `if (disposed) return` 跳过；接着又发现 `flush → 清状态 → 写` 顺序下，写的时候读到的
   是**已清空**的状态 → 写出 `squads: []`。改成「入队时同步取快照并压好」。
3. **超时定时器 unref**：`timer.unref()` 之后事件循环一空进程就退出，超时永远不会发生
   （自检表现为 unsettled await）。去掉 unref，并把这个理由写在代码旁边。
