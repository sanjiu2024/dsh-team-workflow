# REQ-011 · 小队成员独立化：不走 subagent，会话点得进去

- **状态**：草稿（§6 方案待用户拍板 A / A′ / C）
- **对应版本**：`1.15.0 → ?`（待 §6 定完：若保留旧用法则 minor，若换掉 `squad_add` 语义则 major）
- **提出**：用户 2026-10-08，在 REQ-009 交付后试用时提的两条原话：
  1. 「你这个小队不还是调用了 deepseek harness 的 subagent，我要的是完全独立于 subagent 的小队」
  2. 「小队的进入会话完全用不了」

---

## 1. 要做什么

把 REQ-009 那版小队的**成员机制换掉**：现在的成员是主 agent 用 `subagent_*` 工具派出来的**子代理会话**，
小队只是个壳。改成**小队自己拉起成员、自己驱动**，不经过 `subagent` 工具、不用子代理会话。

同时修掉「进入会话」——它现在**完全用不了**，根因见 §5（不是调错了方法，是拿子代理会话当成员，
天生进不去）。

## 2. 为什么（不做的后果）

- 成员是子代理会话 → 被 `hasApiSessionSubagentOwner` 挡在 `sessionController` 之外 → 点不进去、
  也读不到它的会话（面板只能显示黑板上一句结论，看不到成员在干嘛）。
- 用户对「小队」的期待是**独立的多 agent 编排**，不是 dsh 子代理的一层皮；这层皮一旦被看穿，
  功能再全也不可信。

## 3. 不做什么

- **不重造 agent runtime**：模型调用走 `ctx.llm`、会话走 `sessionController`/`ctx.agents`，
  不自写 HTTP 客户端、不自造 `UserMessage` 的解析链。
  （用户选过「自己实现 agent loop」（C），但侦察查明：`ctx.tools.execute` **缺 `agent` 就会在错的
  cwd 里改文件**（§5），所以 C 要么接受这个缺陷、要么照样得造 agent —— 见 §6 的取舍。）
- **不改**黑板权限模型（`authorize` / `agent_id` 仅所有者 / 收队只读）—— REQ-009 那套原样保留。
- **不做跨会话持久化**：小队状态仍是进程内内存。
- **不做成员间直投（`squad_say`）**：现在有路子了（`sessionController.prompt` 能往任意会话投消息），
  但这次不做，记进 §7。
- **不动面板的只读约定**：不加写路由。

## 5. 已知约束（侦察出来的硬事实）

| 约束 | 证据 | 影响 |
| --- | --- | --- |
| 插件能自建会话并投消息驱动 agent，纯 ctx 服务、零 import、零 HTTP | `dsh-api-session-controller/lib/index.js:2847`（`create`）、`lib/types/index.d.ts:163`（`prompt`） | 成员可以不走 subagent 设施 |
| 自建会话是**普通根会话**（meta 只有 cwd/agentPreset，不带 origin/parentSession）→ 会进 GUI 列表 | `dsh-api-session-controller/lib/index.js:450-458` | 「点得进去」能实现，代价是会话列表会变长 |

| `create()` **不能指定模型**（`agentPreset` 只是 preset id） | `types/types.d.ts:283`、`dsh-agent-preset-registry/lib/types/definition.d.ts:4-13` | 模型要另设 |
| `selectModel()` 能定模型，但**会改全局默认模型** | `dsh-api-session-controller/lib/index.js:720-745`，副作用 `:737` `agentDefaultModel.saveSelection` | 必须绕开（否则建个成员就把用户默认模型改了） |

| 裸 import `@deepseek-ai/*` 不可行（本包零依赖） | 侦察实测 `ERR_MODULE_NOT_FOUND`；可行替代 `ctx.loader.import`，本包已在用 `lib/scheduler.js:933` | 要 import 宿主包只能走 `ctx.loader` |
