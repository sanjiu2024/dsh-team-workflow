# REQ-011 · 小队成员独立化：不走 subagent，转录在面板里看

- **状态**：已完成
- **对应版本**：`1.15.0 → 1.16.0`（minor：换掉成员机制、删 `squad_add`、加 `squad_spawn`）
- **提出**：用户 2026-10-08，在 REQ-009 交付后试用时提的两条原话：
  1. 「你这个小队不还是调用了 deepseek harness 的 subagent，我要的是完全独立于 subagent 的小队」
  2. 「小队的进入会话完全用不了」

---

## 1. 要做什么

把 REQ-009 那版小队的**成员机制换掉**：现在的成员是主 agent 用 `subagent_*` 工具派出来的**子代理会话**，
小队只是个壳。改成**小队自己拉起、自己驱动**：

- 模型调用由小队自己发（`ctx.llm.stream`，配 dsh 公开的 `BlockAssembler` 拼流）；
- 工具由小队自己执行（rc.x 的**公开 shell 服务** + 我们自己实现的 fs 工具），**不借 dsh 的工具执行**、
  不造 agent、不建 dsh 会话；
- 转录由小队自己存（进程内），**面板直接渲染它** —— 这就是「进入会话」的新形态：
  成员不是会话，所以不再有「打开一个会话」这回事，而是在面板里看它。

用户对这条路的选择是明确的（在「子代理皮」与「自持 loop」之间选了后者），代价见 §3。

## 2. 为什么（不做的后果）

- 成员是子代理会话 → 被 `hasApiSessionSubagentOwner` 挡在 `sessionController` 之外 → 点不进去、
  也读不到它的会话（面板只能显示黑板上一句结论，看不到成员在干嘛）。
- 用户对「小队」的期待是**独立的多 agent 编排**，不是 dsh 子代理的一层皮；这层皮一旦被看穿，
  功能再全也不可信。

## 3. 不做什么

- **不借 dsh 的 agent / 会话设施**：成员不是 agent、不是会话 —— `ctx.agents` /
  `sessionController` / `ctx.tools.execute` 一个都不碰（最后一条缺 `agent` 就会在错的 cwd 里改文件，
  见 §5）。成员的工具因此是**我们自己实现的**（§6.3）。
- **不重造模型客户端**：模型调用走 `ctx.llm.stream`，chunk 拼装用宿主公开的 `BlockAssembler`
  （`ctx.loader.import` 取），不自写 HTTP 客户端、不自己拼 tool-call-delta。
- **不自建审批通道**：成员没有审批（§6.4 已写明代价），这次不做。
- **不改**黑板权限模型（`authorize` / 收队只读）—— REQ-009 那套保留，只把「身份从哪来」换掉。
- **不做跨会话持久化**：小队状态与转录仍是进程内内存。
- **不做成员间直投（`squad_say`）**：只能靠黑板，记进 §7。
- **不动面板的只读约定**：不加写路由。
- **不自动建 worktree、不自动合并分支**：都由主 agent 决定。

## 6. 方案

### 6.1 一句话

小队自己驱动成员：**自己发模型请求、自己执行工具、自己存转录**。成员不是 dsh 会话、不是 agent，
面板直接渲染它的转录。

### 6.2 成员的一轮怎么跑

```text
squad_spawn（squad / member / role / task / worktree / model? / provider?）
  → 成员那一行落库（status = 在跑），**不 await**：当场在后台跑起来
  → 循环（最多 maxSteps 步）：
       ctx.llm.stream({provider, model, system, messages, tools, signal})   ← 公开服务
       BlockAssembler 拼流 → 文本 + tool calls + usage + finish
       把 assistant 这一条追加进转录（onEvent 也落成员转录，面板看的就是它）
       没有 tool calls → 收工（状态 = 完成）
       否则逐个执行 tool call（我们的执行器）→ 每个 call **恰好**回一条 tool 结果 → 下一轮
  → 异常 / 超步数 / 被 abort → 状态 = 卡住（理由进 note 与黑板）
```

`system` 是 provider 的 system 槽（不属于 `messages`），每一轮都带；`messages` 自己裁：
保留第一条任务 + 尾部 `keepMessages` 条，且窗口不从 tool 结果开始（`lib/squad-loop.js`）。

- 模型调用：`ctx.llm.stream`（`dsh-llm/lib/types/index.d.ts:412`）；chunk 拼装用**公开的**
  `BlockAssembler`（同文件 `:25`，它会做块索引关联，并在 max-tokens 截断时丢掉不可执行的 tool call）。
  本包零依赖，宿主包只能 `ctx.loader.import`（`lib/scheduler.js:933` 已有先例）。
- 档位 → provider/model：读本包自己的 `team/agent-settings.json`（`subagents.provider` + `tierTools`），
  与预设里 `tool-subagent-<tier>` 用的是同一套（`lib/preset-gen.js:334-355`）；
  上下文预算用 `ctx.llm.resolveModelInfo(provider, model)` 的 `contextWindow` / `defaultMaxTokens`。
- **上下文自己控**：member 转录会长，按「保留最近 N 条 + 超长工具输出截断」自己压（我们不是会话，
  用不了 dsh 的压缩服务）。两个上限写成模块常量。

### 6.3 成员的工具（自己实现 —— 这就是 C 的代价本体）

| 工具 | 实现 | 边界 |
| --- | --- | --- |
| `read` | `node:fs` | 路径必须落在**该成员自己的 worktree** 内；行数 / 字节上限 |
| `write` / `edit` | `node:fs` | 同上 |
| `grep` / `glob` | 自己走 fs 遍历（零依赖，跳过 `.git` / `node_modules` / `.dsh-worktrees`） | 同上 |
| `bash` | **`ctx.shell.resolve` + `ctx.shell.execute`**（公开服务、无需 session） | 显式传 `sandboxPolicy`，`workspaceRoot` = 该成员的 worktree |
| `board` | 直接写本进程的黑板 | 身份 = 这个成员（`from` 由服务端判定，不给参数） |

**bash 为什么走 dsh 的服务、而不是裸 `spawn`**：`ctx.shell.resolve/execute` 接受**完整** `sandboxPolicy`
（`dsh-shell/lib/types/types.d.ts:55-98`）并照它 confine；裸 spawn 什么保护都没有。
调用形状（真实先例 `dsh-tool-bash/lib/index.js:683-686`）：

```js
const req = {
  command, workdir: wt, timeoutMs, stdoutMaxBytes, signal,
  sandboxPolicy: { ...ctx.sandboxPolicy.resolve(), workspaceRoot: wt },
};
const r = (await ctx.shell.execute(ctx.shell.resolve(req))).result();
// 被沙箱拦下**不抛错**：读 r.sandbox.denied；输出是 r.stdout/r.stderr = {text, truncated, spillPath?}
```

### 6.4 安全代价（写在明处，不藏）

- **没有审批**：dsh 的审批服务硬依赖真实 Session 的「开着的 turn」（§5），C 下拿不到；也不自建问答通道。
  替代品是「沙箱策略 + 路径钉死」：bash 走 confine，fs 工具只认 worktree 内的路径。
- **`danger-full-access` 下 confine 会被跳过**（`dsh-bash-sandbox/lib/index.js:68-74`）→ 此时成员的 bash
  等于裸 spawn，只剩 timeout / 输出上限 / 环境变量覆盖 / 凭据 scrub。本机当前正是这个模式（用户自己的设置），
  所以「有沙箱」在这台机器上**不构成额外保护** —— README 要如实写，不能让人以为有。
- **转录不落盘**：进程内，dsh 重启即失（用户要的）。两道内存护栏：条数（`TRANSCRIPT_LIMIT`）
  与**单条正文**（`TRANSCRIPT_TEXT_MAX`）—— 光限条数挡不住「一条 128KB 的 assistant 消息 × 200 条」。
- **`bash` 可以整个关掉**（`team/extensions/squad.json` 的 `bash`）：在 `danger-full-access` 的
  机器上，bash 等于宿主权限且没有审批（第 3 层审查的结论），**关掉它才是本包唯一能提供的真隔离** ——
  成员只剩钉在工作区里的 fs 工具。默认开，因为要跑测试/构建的成员离了它干不了活。
- **`.git` 不给碰**：`resolveInside` 拒绝路径里任何一段叫 `.git`（`grep`/`glob` 早就不遍历它，
  但写口原来能到 `.git/hooks/*` —— 那是**持久后门**：成员种一个 hook，用户之后每次提交都跑它）。
- **写盘这一层的加固（都不是完整隔离，残留写在代码注释里）**：
  · `O_NOFOLLOW` 打开：`resolveInside` 是「先校验、后使用」，中间那次系统调用可以被后台
    bash 换掉（TOCTOU）；`write` 还去掉了 `O_TRUNC`（截断发生在 open 那一刻 —— 等查完再拒
    就已经把目标 inode 清空了），改成 open → 查 → 自己 truncate；
  · `edit` 用**同一个** `O_RDWR` 句柄读-改-写（先关再开留一个替换窗口）；
  · **硬链接单独查**（`nlink > 1` 就拒）：`O_NOFOLLOW` 管不了硬链接，而 `O_TRUNC` 会把
    工作区外那个 inode 直接清空；
  · `squad_spawn` 存 worktree 的 **canonical 路径**（realpath）：软链形式的根不再让「成员的
    世界」悄悄变成它指向的地方。
  · 残留（第 3 层审查逐条确认过，都是**明确接受**）：中间目录被换（Node 没有 `openat`）、
    Windows 没有 `O_NOFOLLOW`、`nlink` 检查与写之间仍有加硬链接的窗口（要彻底解决得靠内核级
    隔离，不是 Node 能做到的）。要真隔离用 `bash: false` —— 那些窗口在 `danger-full-access`
    下本来就没有边际意义（那种权限用 bash 直接就写外面了）。

### 6.5 成员身份与黑板（对 REQ-009 的改动）

## 7. 天花板（做完之后仍不支持的）

- **没有审批通道**：成员不会问、也没地方问（§6.4）。要审批就得自建问答通道，这次不做。
- **沙箱在 `danger-full-access` 下等于没有**：confine 被跳过（§6.4）。
- 转录不落盘：dsh 重启即失（用户要的）。
- **信任边界包含本机的其它进程**：三个只读路由只校验回环 + 同源，没有会话鉴权（与调度器面板
  同一档）。要让本机任意进程读不到小队内容，就得给路由加 token/会话绑定 —— 这次不做，记在这里。
- **所有者可以把成员的根指到任何目录**（`squad_spawn` 的 `worktree`），而且**默认 `bash: true`
  时那个根根本不是边界**：成员能读写工作区外的任何东西，也能把读到的内容发给外部模型。
  这不是提权（所有者本就有全部权限），但它是**要用户显式承担的风险**：别把成员的根指到
  放着密钥的目录；要真把成员关在那个目录里，就得 `bash: false`（那时 fs 工具的
  `resolveInside` + `O_NOFOLLOW` + `nlink` 才是边界）。
- 成员不能派成员：没有嵌套。
- 不做成员间直投（`squad_say`）：C 下就是「往对方转录里塞一条」，但这次不做。
- 成本（钱）列：仍无定价数据（REQ-010 §6 已证）。
- 不走 dsh 的上下文压缩：成员转录靠自己的截断策略（§6.2）。

## 8.1 上线后第一次真用就发现的 bug（1.18.1 修）

**现象**：真机 `squad_spawn` 两个成员全卡在「基础设施失败：dsh-llm 没导出 BlockAssembler /
createToolResultMessage」——成员循环根本没起来。

**根因**：不是宿主缺导出，是 `loadKit` 用错加载方式 —— `loader.unwrapExports` 按 `__esModule`
语义把命名空间换成 `default`（`cordis-plugin-loader/lib/index.js:664`），而 dsh-llm 的 default 是
函数、命名导出在命名空间上，于是取到 `undefined`。实测
`unwrapExports(namespace).BlockAssembler === undefined`。

**为什么自检漏了**：`scripts/selftest-squad.mjs` 的 loader 桩是裸对象（无 `__esModule` /
`default` / `unwrapExports`），那句 `unwrap(...)` 恰好原样返回它。**桩与真契约不一致 = 假绿。**
这跟 §5 里「服务只走 `get()`」那条教训是同一类，只是这次漏在 loader 上。

**修**：`loadKit` 三个来源按序找（命名空间 → default → unwrap 结果）；桩改成真形状并加断言钉住
形状；反向实验（改回只信 unwrapExports）→ 小队自检 5 项红。

**教训**（给下次写桩的人）：桩要照**真契约**造，不是照「能跑通」造 —— 越是"帮它简化"的地方，
越容易把线上会炸的那条路径从测试里删掉。

第 2 轮复核又逮出两条（都是上面第 1 轮修复的**不彻底**处），也修了：

| 级别 | 问题 | 修法 |
| --- | --- | --- |
| P1 | `edit` 先 `O_RDONLY` 读、关掉、再 `O_WRONLY\|O_TRUNC` 写：两次 open 之间留一个替换窗口（换成硬链接就能把旧内容写到工作区外的 inode） | 改用**同一个** `O_RDWR\|O_NOFOLLOW` 句柄读-改-写 |

过程中被自检逮住的**真 bug**（不是测试写错）：`globToRegExp` 分几次 `.replace` 替换 `*` / `?`，
前一次塞进去的 `(?:.*/)?` 被后一次二次加工成 `([^/]:.[^/]*/)` —— `**/*.js` 一条都匹配不上。
改成一次替换到底，并补了 glob 语义单测（`**/` 跨目录也能零层、`*` 不跨 `/`）。
