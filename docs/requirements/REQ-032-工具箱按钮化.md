# REQ-032 · 工具箱：CLI 高频命令的按钮化

- **状态**：已完成
- **对应版本**：`2.13.0 → 2.14.0`（加能力 → minor）
- **提出**：2026-10-31，用户原话「直接把 patch 写成一个按钮，点击按钮可以 patch 补丁，还可以撤销补丁，
  把使用命令的大部分东西全部改为能在 dsh 主页面有个按钮可以直接打开」

---

## 1. 要做什么

主界面会话头加一个**「工具」按钮**，点开是一个面板：

- **补丁两个大按钮**：应用补丁 / 撤销补丁（86 条宿主补丁的 apply / revert）
- 其余 CLI 高频命令也是按钮：重生成团队预设、应用节流配置、定时任务开/关、
  安装状态、插件清单、技能清单、记忆层检查、lens 检查、落盘小队、今日账单
- 顶部一行**活状态**：版本、补丁进度、团队预设产物时间、各子系统开关

## 2. 为什么

这些操作改的都是**本机状态**（宿主安装目录的 JS、预设产物、profile 接线），以前只能开终端敲
`dsh-team xxx`；敲错一个参数，后果不是报错而是「半个环境被改」。按钮把参数固定成白名单，
顺带把「现在什么状态」摆在眼前。

## 3. 不做什么

- **不替代 CLI**：`dsh-team` 仍然全功能，面板只是常用项的子集（`install` / `uninstall` 这类
  会动 profile 的**故意不放进按钮**，避免误点把插件卸了）。
- **不开任意命令执行口子**：前端只能传 `op` 名，服务端白名单之外一律 400。
  不做「把命令原文发给后端跑」那种设计。
- **不做实时日志流**：一次操作一段输出，够了；要盯长时间任务用 CLI。

- [x] `node scripts/selftest-toolbox.mjs` 全绿（6 项）
- [x] 未知 op → 400；危险 op 不带 `confirm: true` → 428；非回环 → 403；跨源 → 403

## 5. 已知约束

| 约束 | 证据 | 影响 |
| --- | --- | --- |
| 一个包只有一个客户端入口 | `lib/client.js:5-6`（`clientExportOf` 只认 `exports["./client"]`） | 面板只能并进 `lib/client.js`，不能另开文件 |
| 会话头是 list 型子槽位，不自动连 `main` | `lib/client.js:809-815` | 按钮必须自己 `layout.selectPanel(id)` |
| `purge.apply` 要枚举宿主目录 | `lib/purge/core.js` 的 `gatherState` | 状态查询较慢，面板只在进入/操作后刷新，不轮询 |
| CLI 跑起来是子进程 | `bin/dsh-team.mjs` | 慢操作（preset install）有 180s 超时上限 |

## 6. 方案

1. **服务端** `lib/toolbox.js`：
   - `OPS` 白名单（13 项）：`args: null` 表示由本模块直接调 `lib/purge/core.js`，
     其余交给 `bin/dsh-team.mjs`（与命令行行为逐字一致）；
   - 路由 `/api/team/toolbox`：GET 状态、POST 执行；回环 + 同源校验；`confirm` 二次确认；
   - 状态聚合全 try/catch —— 任一子系统挂了降级成文本，不把整块面板打红。
2. **客户端** `lib/client.js`：`ToolboxPage`（状态卡 + 危险组 + 只读组 + 输出区）、
   `ToolboxButton`（会话头 order 14，小队是 13）。
3. **接线** `lib/index.js`：`installToolbox(ctx, { root, subsystems })`，`subsystems` 传活状态。

## 7. 天花板

- 面板只覆盖「高频 + 幂等」的命令；`install` / `uninstall` / `mc install` 这类要下载或改 profile 的
  仍走终端（按钮里也能加，但那是另一件事，得先想清楚回滚）。
- 打补丁后的「重启 dsh」不会自动做：`purge.apply` 改的是**已加载**的 JS 文件，重启才生效；
  面板只在输出里提示。
- 撤销补丁依赖备份原件（`$DSH_HOME/dsh-purge/host-backups`）；备份被删过就还原不了，
  面板如实报错，不做「假装成功」。
