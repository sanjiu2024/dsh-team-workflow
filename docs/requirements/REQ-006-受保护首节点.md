# REQ-006 · 会话重载失败：受保护首节点被注入块顶掉

- **状态**：已完成
- **对应版本**：`1.10.0 → 1.10.1`（只修 bug，patch）
- **提出**：2026-10-04，用户重启 dsh 后打开历史会话，报
  `stored session "session-c1eda5a4-…" is corrupt: … SessionFormatError: system/message requires a protected first surface head`

---

## 1. 要做什么

用户原话（重启后看到整段报错，然后在选项里选了）：

> 都修复

拆成两件事，缺一不可：

1. **把已经坏掉的会话日志修好** —— 那些会话要能重新打开，历史、记忆、工具结果一条都不能少。
2. **修掉产生坏形状的根因** —— 不然修完再聊两句又坏了（而且用户会以为「修好了」）。

## 2. 为什么（不做的后果）

本机 25 个会话里 **19 个打不开** —— 凡是装过 magic-context 并续聊过的会话全部报废。

要害在于**校验时机**：坏形状是在**写入时**产生的，但校验只在**重载时**跑。
于是它安静地写了好几天，直到用户重启（或续聊）才炸 —— 而那一刻正是他最需要
那段历史的时候。三个会话的坏形状还是「每次续聊都会新写一个」，所以这个 bug
不是静态的损坏，是**持续产生**的损坏。

## 3. 不做什么

- **不重排序、不重新编号**。修数据时只改被顶掉的那两个事件的类型，seq 一律不动
  （重排要连带改 `sourceEventSeqs` / `shadowedSeqs` / `headerSeq` / `targets` …，
  风险高一个数量级，收益为零）。取舍见 §6。
- **不动 dsh 自带的压缩与持久化**。它们的行为是自洽的，问题在我们这边。
- **不把注入块塞进 `decision.messages`**。那条路会碰到 agent-loop 的
  step-0 回合结束判定，为了绕开一个校验去改回合语义不划算。
- **不自动修「首节点是有内容的节点」那种坏法**。只有那两个已知空占位块才自动修，
  别的一律拒修并打印出来 —— 从 surface 上摘掉有内容的东西等于让模型少看一段，
  这个决定不能由脚本替用户做。
- **不碰 v3 老格式**（本机只有 1.10.x 这一条线）。

## 5. 已知约束（侦察出来的硬事实）

| 约束 | 证据 | 影响 |
| --- | --- | --- |
| surface 首节点必须是 `system/message`，后续再来的 system/message 会被拒 | `dsh-session-format-v3-to-v4/lib/index.js` 的 `foldSurface`（报错原文即出自这里） | 注入块不能落在空 surface 上 |
| **写入时完全不校验**，只有重载时才校验 | 实测（下段代码）：空 surface 上先 append `user/message`、再 append `system/message`，**不抛**，surface 变成 `[user/message, system/message]` | 坏形状静默写盘，靠「重启才发现」 |
| 首轮 `agent/pre-step` 跑在 `system/message` 落地**之前** | `dsh-agent-loop/lib/index.js:1052`（`systemPrompt.project` 落 system/message；pre-step 在它之前） | 首轮 pre-step 时 surface **必然是空的** —— 这就是先手 |
| unknown + `ignorable: true` 的记录会被整条跳过，不校验 surfaceOp | `dsh-session/lib/index.js:296-303`（`surfaceOpOf` 对未知类型返回 `undefined`）；`Session.fromRestore` 同样早退 | 数据修复可以「降级类型」而不是删数据 —— 内容、seq、时间全留 |
| Magic Context 的注入块**每轮都从 DB 重算** | `vendor/pi-magic-context/dist/index.js:24498`（按需 push `<session-history>`）与 `:24818`（无新增时给占位串） | 推迟一轮落地**不丢内容**，下一轮自然补上 |
| 会话日志是**多帧 zstd、一个事件一帧** | `lib/session-log.js` 的 `scanZstdFrames` / `readSessionLog` / `writeSessionLog` | 重写必须按帧写；帧数与原来不同是正常的 |
| 一个会话目录里 `session.` 开头的文件会被当成第二个会话 | `walk` + 持久化的枚举规则 | 备份**必须**写到会话目录外 |

实测脚本（写进 §8 引用）：

```js
// 空 surface 上，老写法（直接 append 注入块）不报错 —— 这是「静默」的直接证据
const s = Session.create("probe");
s.append("user/message", inj, { surfaceOp: "append" });   // 不抛
s.append("system/message", sys, { surfaceOp: "append" }); // 也不抛 → surface = [inj, sys]
```

## 6. 方案

两段，先数据后代码。

**第一段 · 修数据**（`scripts/fix-surface-head.mjs`，新增）：对每个加载不了的日志，

1. 用**下标**走一遍 surface 折叠（`replace` 会把新节点插在被替换那段的位置上，
   所以 surface 里的 seq 不单调，只有下标可靠），找出「第一个 system/message 之前
   的表面节点」；
2. 它们必须**正好**是那两个已知空占位块，否则拒修并打印内容；
3. 把它们改成 `plugin:magic-context/session-history-injection` + `ignorable: true`，
   **原地保留 seq / time / 原 payload**（放进 `data` 里留档）；
4. 重算被波及的 `compaction/prune` / `compaction/summary` 的
   `shadowedRange` / `shadowedSeqs` 和依赖它的 `replace` 范围 —— 受保护头既不能被
   shadow 也不能被 replace 盖住，不重算就会接着报
   `shadowedSeqs do not name an exact current surface span`；
5. **写盘前**用 dsh **自己的加载期校验**（`dsh-session-format-catalog` +
   `findDshModules()`）复验内存结果，不通过就不写；写完再验一次。

**第二段 · 修根因**（`lib/mc.js`）：`landOnSurface` 开头加守卫 —— surface 上还没有
`system/message` 时**这轮不落地**（返回 `reason: "no-protected-head"`），并在
pre-step 钩子里打印一行日志说明。因为注入块每轮从 DB 重算，推迟一轮零损失。

**为什么不选别的路**：

| 方案 | 否掉的理由 |
| --- | --- |
| A. 重排 + 重新编号整个后缀 | 要改 `sourceEventSeqs`/`shadowedSeqs`/`headerSeq`/`targets` 全部引用并重排 span，收益为零 |
| C. 直接删掉 `surfaceOp` | 试过：会留下第二个错（span 校验），而且丢掉来源信息 |
| D. 注入块改走 `decision.messages` | 影响 agent-loop 的 step-0 回合结束判定（`:962-966`） |

## 7. 天花板（做完之后仍不支持的）

- **并发保护是「三道判据 + 明说取舍」，不是排他锁**：脚本写盘前三道拦 ——
  ① `heldOpen()`（Linux 扫 `/proc/<pid>/fd`，按 dev/ino 比）；② 文件的 mtime 在 120s 内
  （`DSH_LIVE_MS` 可调）；③ 读完之后 mtime/size 又变了。但 dsh 的 append 是**每批开一次
  fd、写完就关**（`dsh-session-persistence-jsonl` 的 append 路径），所以 ① 常常抓不到它，
  ②③ 才是真正承重的。
  **没有做成「一发现 dsh 在跑就整批拒写」**：用户实际就是在 dsh 会话里跑这个脚本修历史
  会话（本次 18 个就是这么修好的），硬门会让工具没法用，而历史会话本来也不会被追加。
  代价是：如果 dsh 正在往某个文件追加而我们恰好同时改它，dsh 那批事件会写进已被 rename
  换掉的旧 inode（静默丢事件）。**要修「正被追加的会话」，先停掉 dsh**，别无它法。
- **本会话自己修不了**：`session-ae61f056…` 正在被 agent-loop 追加（`dsh-session-persistence-jsonl/lib/index.js:3218`），
  改写它就是和它抢文件。上面三道判据会把它挑出来跳过（实测三次都跳过了）。
  **退出本会话、dsh 重启后**再跑 `node scripts/fix-surface-head.mjs --fix` 即可（它会认出同一个 bug）。
- **新会话的第一轮看不到 MC 注入块**：守卫让它在 `system/message` 就位后的下一轮才落地
  （首轮 pre-step 时 surface 必然是空的）。代价是首条模型请求少一段记忆上下文。
- **只认那两个空占位块**：首节点是带内容的节点时不自动修（见 §3）。
- 已经写坏的>2 个节点、或首节点不是 `user/message` 的其它坏法，本脚本不覆盖。
