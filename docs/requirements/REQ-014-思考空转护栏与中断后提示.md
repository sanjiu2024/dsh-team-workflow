# REQ-014 · 思考空转护栏 + 中断后自动提示

- **状态**：已完成
- **对应版本**：`1.18.1 → 1.19.0`（新增能力 → minor）
- **提出**：用户，2026-10-09，原话：「现在ai会莫名其妙思考时进入循环，你看看有没有什么解决办法」；
  在给出 A–E 五个选项后，用户勾选 **D（中断后自动接提示）+ C（思考体量护栏）**。

---

## 1. 要做什么

在 REQ-013（逐字重复 → 中断）之上补两层，专治「不是逐字重复、但一直在绕」的思考循环：

- **C · 思考体量护栏**：一次流式模型调用里，`reasoning` 累计字符数超过阈值（默认 **20000**）
  就判定为空转 —— 不管它写的是不是新句子。这是「一直在产新文字但毫无进展」的唯一可用信号
  （宿主没有 step/turn/思考上限，见 §5）。
- **D · 中断后自动接提示**：命中任何一条（逐字重复 / 体量超限）时，先 `cancel` 掉当前 turn，
  再 `followup` 一句提示：「检测到你在思考里绕圈（原因），已中断这一轮。请直接给结论，或换一个
  策略，不要重复同一思路。」—— 把「静默掐掉」变成「掐掉并告诉它为什么」，模型有机会自己出来。

## 2. 为什么（不做的后果）

REQ-013 只认逐字重复（16 字符 × 4）。真机上观察到的循环形态是**换个说法反复绕同一个结论** ——
字面不同，那层抓不到；用户看到的现象就是「莫名其妙一直在想」。宿主侧没有任何兜底（§5）。
不做的话：模型可以在一轮里想几万字符，烧 token 且不产出，只能人工按停止。

## 3. 不做什么

- **不做近似/语义相似度检测**（用户这次没选 B）：阈值难调、误判排比与引用，等真需要再说。
- **不做时间型护栏**：慢 provider 和循环 provider 在时间上无法区分，会误杀「慢但有效」的深度思考；
  体量是确定性的、可测的。
- **不检测工具调用循环**（沿用 REQ-013 的边界）。
- **不无限提示**：同一会话里自动提示有次数上限（默认 3 次），用完只静默中断 —— 否则会变成
  「提示 → 又绕 → 再提示」的新循环，每一轮都花钱。
- **不改思考档位/模型配置**（E 没选）。
- **不动 REQ-013 已定的字面阈值**（16 字符 × 4）。

## 4. 验收标准

- [x] `reasoning` 累计**超过** 20000 字符 → 命中；19999 / 正好 20000 → 不命中；阈值只在 reasoning 上累计，`text` 不计（正文 30000 字符不触发）。
- [x] **只拦 AgentLoop 自己的请求**：带同一 `sessionId` 的压缩/会话标题调用（`purpose` 有值）原样旁路，不得取消真人 turn。
- [x] 命中后：`cancel({kind:"hook",reason},{keepInbox:true})` 调用一次，且**紧接着**投递一条提示消息（`followup`），文本包含「绕圈」与中断原因。
- [x] 提示有预算：同一 session 最多 3 次；第 4 次起只 cancel、不再 followup。
- [x] 提示构造不出（宿主没导出 `createUserMessage`）时**只 cancel**，不抛错、不卡住，并记一条 warn。
- [x] 逐字重复（REQ-013）行为不回归：原有专项断言全绿（`npm test` EXIT=0）。
- [x] 反向实验：默认上限改成 `Number.MAX_SAFE_INTEGER` → 默认值断言红；删掉 `followup` → 提示断言红。
- [x] `npm test` EXIT=0；`package.json` = `CHANGELOG.md` 首节 = `1.19.0`。

## 6. 方案

1. **抽出宿主导出加载器** `lib/dsh-exports.js`：把 REQ-011 §8.1 那套「命名空间 → default → unwrap
   结果」的查找逻辑收成一个模块，`squad.js` 与 `repeat-guard.js` 共用（一个地方知道那个陷阱）。
2. `lib/repeat-guard.js` 扩展（同一个 `llm/stream` 钩子）：
   - 逐字重复（原样保留）；
   - **只认 AgentLoop 请求**：`options.purpose !== undefined` 同步快筛掉压缩/会话标题，再用
     `isAgentLoopRequest(options)` 严格门禁（见 §5 的 2026-10-09 补记）；
   - **reasoning 字符累计**：一次流式调用内累加所有 reasoning block 的字符数，超过
     `maxReasoningChars` 即命中（`text`/`tool-call` 不计入，等于上限不算超）；
   - **动作**：`cancel` + （预算内）`followup(提示)`；预算按 `sessionId` 记，默认 3 次；
     `createUserMessage` 拿不到就只 cancel 并 warn。
3. 配置 `team/extensions/repeat-guard.json` 增 `maxReasoningChars`（20000）、`nudge`（true）、
   `maxNudgesPerSession`（3）。
4. 自检 `scripts/selftest-repeat-guard.mjs` 增 C/D 的断言与反向实验；`selftest-squad.mjs` 改用共享
   加载器后必须仍全绿（回归）。

## 7. 天花板

- **语义循环仍抓不到**：换了说法、或在不同结论间来回横跳但每段文字都不重复、体量也不超阈值时，
  两层都不会命中。
- **体量阈值是「一刀切」**：单步思考接近 20000 字符但确实有效的深度任务会被误中断（可调高或
  `enabled:false` 关掉）。
- **提示本身也可能被无视**：模型下一轮仍可能继续绕；预算用完后就只剩静默中断。
- **只在 `llm/stream` 可见的范围内生效**：非 AgentLoop 请求（hand-built、压缩、会话标题）原样旁路
  —— 这一条靠 `isAgentLoopRequest` 门禁成立，**不是**靠「没有活 Agent」（压缩/会话标题与真人 turn
  共享同一个 `sessionId`，能找到活 Agent，见 §5）。
- **体量按「一次流式调用（attempt）」计数**：`llm/stream` 只给得到 `sessionId`，拿不到 turn/step
  （§5），所以同一步被重试时每次重新计数。**更该知道的是多 step**：一个 turn 里 10 个 step 各思考
  19000 字符（合计 19 万）永不命中 —— 这条比「重试重新计数」后果大。要按 turn 累计得换别的挂点，
  本次不做（std 测 2026-10-09 指出）。
- **提示预算是「每会话累计 3 次」，不按时间窗重置**：用完就只剩静默中断，要恢复得重开会话。
  不按「新的用户消息」重置是因为自动提示本身也是一条 `user` 消息（`source.kind === "user"`），
  分辨不出「真人发言」，那样重置等于把上限作废。

### 自查发现（写测试时自己踩的两处）

- **体量用例的测试数据踩了第一层**：`"x".repeat(20000)` 本身是逐字重复，被 REQ-013 那层先抓住 ——
  测的就不是体量护栏了。改用非周期文本（`0x4e00 + index % 997`），并加一条断言把这件事钉住。
- **只传显式 `limits` 的测试测不到默认值**：把默认上限改成永不触发，测试居然还是绿的（反向实验①
  第一次没红）。补上「默认值本身是契约」的断言 + 两条**不传 limits**、走出厂默认的行为断言。

### 自查（替代性最坏后果分析，**不是独立审查**）

power 没跑成，下面是我自己按 B 类问题过的一遍，明确标注来源：

1. **自动补的 user 消息会出现在对话里**：它是一条真正的 user 角色消息（`UserMessage.source` 的
   类型只允许 `{kind:"user"}`），所以 GUI 里看起来像用户自己说的。文案以「检测到…」开头、且
   按会话限 3 次，不会刷屏；但这是**已知的观感代价**，要更干净得改 dsh 的消息来源类型，本次不做。
2. **误杀长思考**：20000 字符/attempt 是「空转线」，不是「深度线」；接近这条线的有效长思考会被
   中断（可调高或 `enabled:false`）。损失是这一轮的思考，**不丢用户输入**（`keepInbox:true`）、
   **不丢已生成内容**（interrupt safe-prefix 会落库）。
3. **`cancel` 后立刻 `followup`**：取消后投递的唤醒输入排在下一轮，等被中止的活动收敛到 idle 时
   运行（`dsh-agent/lib/types/runtime-types.d.ts:176-181`）；若命中时已经 idle，`cancel` 是 no-op，
   `followup` 正常起一轮。
4. **状态泄漏**：`nudges` 按 sessionId 记，已补 `session/disposed` 清理 + `dispose()` 里 `clear()`。
