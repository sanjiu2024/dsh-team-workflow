# REQ-024 · 操控电脑 2.0：跨平台核心库 + 多前端

- **状态**：草稿（待 review）
- **对应版本**：`2.6.3 → 2.7.0`（加能力 minor；第一个里程碑保持现有 7 个工具向后兼容，故不动 major）
- **提出**：用户，2026-10-19。原话：「写长期产品」「核心库 + 多前端」「跨平台 Win/mac/Linux」「直接在这个工作流里面」「CLI → DSH 插件 → MCP」

---

## 1. 要做什么

把现在这套**只跑 Windows、只给 DSH 用、只靠模型自己看截图找坐标**的操控电脑能力，做成一个能长期维护、能给别人用的产品。用户明确要的形态：

1. **核心库 + 多前端** —— 内核独立，CLI / DSH 插件 / MCP 各包一层
2. **跨平台 Win/mac/Linux** —— 不再绑死 Windows
3. **放在本仓库里** —— 不另起仓库
4. **前端顺序**：CLI → DSH 插件 → MCP
5. **第一个里程碑**：内核抽象 + Windows 完整实现 + CLI 前端

**观测路线**（本节为推荐，待 review 确认）：采用 **SoM（Set-of-Mark）**——服务端用平台无障碍 API（Win 的 UIA / mac 的 AX / Linux 的 AT-SPI）解析出元素的**坐标和名字**，把编号画到截图上；模型只看到「一张图 + 一份短元素列表」，**回编号而不是回坐标**。无障碍树本身**永远不进模型上下文**。

> 为什么不是「直接喂 UIA 树」：实测过，那样比截图贵 20 倍（见 §5）。

## 2. 为什么（不做的后果）

现有实现（REQ-002，已完成）有三个结构性限制，不改就一直是天花板：

- **绑死 Windows**：`lib/computer.js:617` 一行 `if (process.platform !== "win32") return disabled("仅 Windows")`，mac/Linux 直接没有。
- **绑死 DSH**：直接 `ctx.tools.register()`，别人（Claude Desktop、Cursor、别的 harness）用不了。
- **定位靠猜**：模型自己看截图算坐标。**失败是静默的**——点偏了不报错，继续往下走，最后交付一个错结果。而无障碍树能给出「这个按钮叫什么、能不能点、是不是 disabled」，失败会当场报错。

不做的话，这套东西就只能在这台机器、这个 harness 里用，而且每加一个平台就要改一遍核心文件。

## 3. 不做什么

**沿用 REQ-002 的边界**（这些当初否决过，别顺手加回来）：

- 不做 OCR / 本地视觉识别 —— 读屏靠模型视觉
- 不做窗口管理（激活、拖动标题栏之外的窗口操作）
- 不做录屏 / 连续视觉 —— 单次截图，模型要连续看就连续调
- 不锁键盘（只锁鼠标）
- 不做浏览器协议（CDP）—— 浏览器场景交给现成的 `chrome-devtools-mcp` / `@playwright/mcp`，不在本产品范围内
- 不改 dsh 内核：纯包外插件，只走 `ctx.tools` / `ctx.get` / spawn

**本次新增的边界**：

- **不在本机无法验证的平台上写实现代码**。本机只有 Windows 11，mac/Linux 的驱动**只留接口 + 空实现**，返回明确的「本平台未实现」。**不写看起来能跑、实际没跑过的代码**——那在 §8 里只能记「未验证」，等于虚的。等有机器了再补。
- **不引入运行时依赖**。本仓库铁律是零依赖纯 ESM（`AGENTS.md` §2），核心库也不例外——平台驱动走 spawn 系统自带工具（PowerShell / osascript / xdotool）。
- **不拆 monorepo**。本仓库是单包（`private: true`，无 workspaces），"核心库 + 多前端"用**包内分层**实现（见 §6）。拆 workspaces 会动到现有 `npm test` 与发版流程，收益要等真给别人用才体现，不值当。
- **不动 REQ-002 的现有工具名与行为**。`screenshot` / `mouse_move` / `mouse_click` / `scroll` / `type_text` / `key_press` / `cursor_position` 七个名字、审批语义、锁鼠标语义**全部保持不变**，`scripts/selftest-computer.mjs` 不改也应全绿。

## 6. 方案

### 目录结构（包内分层，不拆 monorepo）

```text
lib/computer/
  core/            平台无关：观测数据模型、元素编号表、寻址语义、安全语义（审批/锁/紧急逃生）
  drivers/
    win32.js       Windows 完整实现（UIA 观测 + SendInput + WH_MOUSE_LL）
    darwin.js      接口 + 空实现（返回「本平台未实现」）
    linux.js       接口 + 空实现（同上）
    index.js       按 process.platform 选驱动
  fronts/
    cli.js         CLI 前端（第一个里程碑）
    dsh.js         DSH 插件前端（保持现有 7 工具契约）
    mcp.js         MCP server 前端（最后做）
lib/computer.js    保留为薄兼容层，re-export 现有 15 个符号，保证 selftest-computer.mjs 不改仍绿
```

**为什么不拆 monorepo**：见 §3。核心库与前端在同一包内以目录边界隔离，导出面用 `package.json` 的 `exports` 收窄（将来要拆随时能拆）。

### 观测链路（SoM）

1. 驱动层调平台无障碍 API，拿到元素列表：`{ id, role, name, bounds, patterns[], enabled }`
2. **服务端过滤**：丢掉 `Text` / `Document` / 纯布局容器节点，只留可交互元素（有 `Invoke`/`Value`/`Toggle`/`SelectionItem`/`ExpandCollapse` 模式）和少数有意义的标签
3. 元素编号 → 存进**服务端**的编号表（元素对象 + 生成时的 UI 版本号）
4. 截图，在图上给每个编号元素画标记
5. 模型看到：截图 + `[3] Button '新建会话'` 这样的短列表
6. 模型回编号 → 服务端查表 → 执行 → **验证**（重读状态确认生效）

**关键设计点**（每条都对应 §5 里的一条约束）：

- **等树稳定**：轮询直到**连续两次查询节点数一致，且树里已经出现有名字的交互控件**（`Button` / `Edit` / `MenuItem` 等）；有超时。**只看节点数会假阳性**——懒加载期间的空壳树（13 个无名 Pane）也是"稳定"的（实测见 §5）。
- **编号会失效**：编号表带 UI 版本号，UI 变了旧编号一律报错，**绝不回退到按旧坐标点击**。
- **失效探测用 `BoundingRectangle`，不用 `Name` / `IsOffscreen`**：实测进程被杀后 `IsOffscreen` 仍返回 `False`、`Name` 返回空串（都是静默的），只有读 `BoundingRectangle` 会抛异常。每次用元素前先读它——**它同时也是 SoM 画编号要用的属性，读一次两用**。
- **动作层优先走 pattern**（`InvokePattern` / `ValuePattern`），实测可用：不抢焦点、不依赖坐标、失败会抛。pattern 不支持时才降级到 SendInput 坐标点击。
- **动作后验证**：每个动作重读状态，不信「应该成功了」。
- **超时 + 拉黑**：单次查询超时就把该窗口降级到纯视觉，不反复卡。
- **视觉兜底**：无障碍拿不到的一律走现有截图 + 坐标路径。

### 为什么是这条路（否决了哪些）

- **直接喂无障碍树** —— 否决。实测贵 20 倍（§5），且树本身啰嗦。
- **纯视觉（现状）** —— 不作为主线。失败静默是结构性问题。
- **纯结构化** —— 否决。Canvas/游戏/自绘 UI 直接放弃，且 UIA 查询可能卡死。
- **用现成的 Windows-MCP / UFO²** —— 不冲突，但**它们是别人的产品**：Windows-MCP 要 Python 3.14+（本机没有），UFO² 是完整 agent（和 DSH 抢方向盘）。本 REQ 要做的是**内核属于自己**的那一层。
- **拆 monorepo** —— 否决，见 §3。

### 平台驱动策略

- **Windows**：完整实现，第一个里程碑交付
- **mac/Linux**：**只留接口 + 空实现**，返回 `{ ok: false, reason: "本平台未实现" }`。前端会如实把这个错误报给用户，**不假装成功**。等有机器了补实现，接口不变。

## 7. 天花板（做完之后仍不支持的）

- **mac/Linux 实际不可用** —— 第一个里程碑只有接口，没有实现。这是 §3 主动选的，不是遗漏。
- **管理员权限窗口注入无效**（UIPI）—— AI 点不到 UAC / 提权软件的按钮，只能如实报错。沿用 REQ-002。
- **Canvas / 游戏 / 自绘 UI 只能走视觉兜底** —— 那些地方没有无障碍树。
- **多显示器 + 缩放未验证** —— 本机单屏 1920×1080 @ 96 DPI，跨屏坐标归一化没测过。
- **不保证复杂多步任务的成功率** —— 第三方基准（OSWorld 2.0）显示 2026 年最好的模型在长任务上也只有 14–20.6%。本产品提升的是**单步的可观测性与可验证性**，不是「无人值守自动化」。
- **浏览器内操作不如 CDP** —— 交给现成 MCP，本产品不碰。
