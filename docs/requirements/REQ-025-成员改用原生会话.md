# REQ-025 · 小队成员改用原生 dsh 根会话

> 状态：进行中 · 提出：2026-10-19 · 对应版本 `2.6.5 → 2.7.0`（加能力 → minor）

## 1. 要做什么

把**成员的驱动层**从"小队自己发模型请求、自己执行工具"换成"**建一个普通 dsh 根会话并投消息**"。
编排层（黑板 / 验收清单 / 审查 / 落盘 / 面板）全部保留。

- **建会话**：照抄调度器的先例 —— `scope.agents.withoutInitiator(() => scope.agents.create({ sessionId, meta: { cwd: worktree, agentPreset }, setup, agentOptions }))`
  （`lib/scheduler.js:1077`，options 在 `:1075`）。`cwd` 钉在成员的 worktree 上（原来靠工具层钉，现在由会话本身钉）。
- **权限随会话**（这是修沙箱那把钥匙）：在 `setup(agentCtx, created)` 里
  `setSandboxMode(agent.session, <小队所属会话的权限档>)` + `setApprovalPolicy(agent.session, "never")`，
  **两条都要回读核对**（`lib/scheduler.js:1048-1061`）。权限档从 `exec.agent` 取 ——
  `lib/squad.js:824-832` 已经在用 `exec.agent.session.header.cwd`，同一处能拿到会话。
- **投消息**：`agent.followup(createUserMessage({ content: [{ type: "text", text: task }], source: { kind: "squad", ... } }))`
  （`lib/scheduler.js:1127`；`createUserMessage` 从 `@deepseek-ai/dsh-llm` 动态 load）。
- **等收工**：`await agent.whenIdle()`（`:1144`），与超时 `Promise.race`；超时走 `agent.cancel`（`:1151`）再等收敛（`:1163`）。
- **收尾**：`scope.sessions.flush(agent.session)`（`:1192`）+ `handle.dispose()`（`:1197`）。
- **工具面**：`agentCtx.tools.restrict({ deny: ["squad_new", "squad_spawn", "squad_close", ...] })`（`:1046`）——
  否则成员能递归建队。
- **黑板 / 验收 / 审查**：**不变**，仍是宿主层工具。已查实宿主层工具对任何 preset 的 agent 可见
  （`@deepseek-ai/dsh-tools/lib/index.js:3058-3074`：`ToolRuntime.view` 把 `layers.global.tools` 整体塞进 inherited，
  scoped 注册只 shadow、只有 restriction 能过滤）；实证是本包为根 ctx 插件、本会话（preset=`team`）里 `squad_*` 工具全在。
- **面板**：成员行加「打开会话」。`uiWorkspace.openSession` 本身可用（REQ-011 已查实，签名见
  `dsh-client-ui-workspace/lib/types/client/navigation.d.ts:15,94`）；REQ-011 当时删掉这条路是因为**子代理会话**
  打不开，根会话没有那个问题（不需要 durable address）。
- **队长通知**：订 `agent/status`（`dsh-agent-loop/lib/index.js:798`，`{status:"idle"|"running"}` 变化时发）、
  `agent/error`（`:880`）、`session/disposed`（`dsh-session/lib/index.js:1930`，现在只订了这一个，见 `lib/squad.js:1190`）。

## 2. 不做什么

- **不删编排层**：黑板、验收清单、`squad_review`、落盘、面板都保留；只换成员怎么跑。
- **不做「隐藏会话」**：已查实 0.2.1-rc.2 做不到（两个隐藏开关 `origin='subagent'` / archived 都同时掐掉驱动，
  见项目记忆 #46）→ 接受成员会话出现在列表里，靠 **cwd = worktree 分组**收敛，不污染当前工作区那一组。
- **不改调度器**、不动预设的档位行（`tool-subagent-std/power/max` 照旧）。
- **不给成员 `squad_*` 工具**（restrict 掉）。
- **不迁移旧小队状态**：进程内内存，重启即弃（与现在一致）。

## 5. 方案

- 新文件 `lib/squad-agent.js`：把调度器那套（建会话 → setup 设权限 → 投消息 → whenIdle → flush/dispose）
  抽成"跑一个成员"的单一入口，`squad-round.js` 的模型/工具驱动那一段删掉、改成调它。
- `lib/squad.js`：`squad_spawn` 时记下**所属会话**（`exec.agent`，已有用法见 `:824-832`）；
  订 `agent/status` / `agent/error` 把收工与出错变成事件。
- 面板（`lib/client.js`）：成员行加「打开会话」，走 `uiWorkspace.openSession(id)`；补 `inject` 声明
  （REQ-011 查实过第一层根因就是漏声明 `uiWorkspace`）。
- 自检：`scripts/selftest-squad.mjs` 里假 ctx 的部分要跟着改；新增"成员工具面被 restrict 住"的断言。
- **验收用的探针**：`命令探针` 小队那条（成员跑三条命令）——它是这次改动的判据。

## 6. 天花板（做完之后仍不支持）

- 成员会话会出现在会话列表里（宿主不给隐藏开关），只是归到 worktree 那一组。
- 不做跨重启的小队恢复（进程内状态，与现在一致）。
- 旧的自持 loop 代码在迁移后删除；若将来要回退，靠 git 历史。

### 没跑的（本机跑不了，如实记）

- **端到端真跑**：本机起不了第二个 dsh（要重启宿主），所以「成员会话真出现在列表里 / 点『打开会话』真跳过去 /
  `followup` 真把任务投进去」这三条**没有真实运行结果**，只有假 ctx 级别的断言。判据那条
  `命令探针` 小队要主 agent 在重启后自己跑。
- `npm test` 一条龙跑不完：链子在第 2 条 `selftest-mc.mjs` 就断了（裸 worktree 缺 magic-context bundle），
  所以上面是**逐条**跑的，不是 `npm test` 的 EXIT=0。

### 已知退化（原生会话里没有这些边界）

- token 预算：从「发下一次请求之前」退到**事件边界**结算 —— 超了仍判停，但一轮可能先跑到 `maxSteps`
  （`selftest-squad.mjs` 的 A2 那条已按新语义改断言）。
- `maxSteps`：宿主自己没有步数上限，靠 `session/event` 上的步数护栏兜。
- 转录：一轮收尾时从会话事件折出来（不再逐步推）。
