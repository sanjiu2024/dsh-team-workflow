# REQ-026 · 小队改成「每个会话独立」

> 状态：进行中 · 提出：2026-10-19 · 对应版本 `2.8.0 → 2.9.0`（改默认行为 → minor）

## 1. 要做什么

把小队状态的归属从**工作目录**改成**会话**：每个会话有自己的一批小队，互相看不见，
新会话从**空**开始。

- **落盘键从 cwd 换成会话 id**：`lib/squad-store.js` 现在按 `workspaceKey(cwd)` 一目录一份
  （`:6` 的注释原话：「一个 cwd 一份文件，读回来时由**当前会话接管**（`owner` 改写…）」）。
  改成一份文件对应一个会话。
- **不再接管**：现在同一目录里开的新会话会把老会话的小队捡走（`owner` 改写成新会话）。
  改完之后**没有这个行为** —— 会话各自读自己那份。
- **看得到的范围收窄到本会话**：面板与 HTTP API 只给**当前会话**的小队（现在给全量、按 owner 分组）。
- **成员 worktree 不能撞名**（这条是这次改动的**必然副作用**，必须一起做）：worktree 落在
  `<主仓库>/.dsh-worktrees/<名字>`，而名字是**全局共享**的。会话独立之后，两个会话各自派一个
  叫「实现-A」的成员就会撞同一棵目录 —— 名字里要带上会话/小队维度。

## 2. 不做什么

- **不迁移旧数据**：现有那几份按 cwd 落的文件（`Desktop-*.json` / `dsh-team-workflow-*.json`）
  不再被读，里面的小队**不会**出现在任何会话里。它们留在盘上可手工查看，但代码不再碰。
  （与 REQ-025 §2 的既有立场一致：小队状态是运行态，不做跨重启/跨版本迁移。）
- **不改成员的语义**：成员仍然是**各自一棵 worktree 里的原生 dsh 会话**（REQ-025）。
- **不改落盘格式的内部结构**（还是 `{squads: [...]}`，还是那套锁与防抖），只换**键**。
- **不动 `squad_*` 工具的对外契约**（名字、参数、返回值不变）。
- **不做「跨会话查看别人的小队」** —— 用户要的就是互不可见。真要看，去看那个会话。

## 3. 验收标准（每条都要能跑）

- [ ] 同一工作目录里的**两个会话**各自 `squad_new` 建队，互相 `squad_status` **看不到对方**
- [ ] 新会话（没有任何小队）打开面板，显示的是**空**，不是上一个会话的小队
- [ ] 会话 A 建的小队，在会话 A 里 `squad_status` 仍然看得到（键没写坏）
- [ ] 两个会话各自派一个**同名成员**（比如都叫「实现-A」），两棵 worktree **不是同一棵目录**，两边都能跑命令
- [ ] `node bin/dsh-team.mjs squad ls` 仍能列出落盘的小队（怎么定「属于谁」写进输出）
- [ ] `npm test` 无新增红（既有红：`selftest-scheduler.mjs` 3 条、`selftest-squad.mjs` 2 条成员工具红）
- [ ] `package.json` 版本 = `CHANGELOG.md` 首个标题 = `2.9.0`，且有同名标签

## 5. 方案

**宿主侧（按侦察给的最小改法）**：

- `persistSquad` 的键从 cwd 换成 `squad.owner`（`lib/squad.js:1147-1151`）。
- `ensureLoaded(callerId)` 用会话 id 做键（`:1154-1186`）。
- **删掉接管**（`:1177-1181` 改写 `owner` / `adoptedFrom`）与 `loadedCwds`（`:1135/1156-1158/1231`）。
- `squad.cwd` 保留，只当展示字段。
- `/squads`、SSE `/events`、`/transcript` 只回**当前会话**的（服务端过滤，别指望客户端）。
- `session/disposed`（`:1220-1233`）**不删该会话那份文件** —— 关掉界面会 dispose 会话，删了就等于
  「关一下窗口小队全没」，代价太大。孤儿文件（会话真没了）留着，见 §6。

**客户端侧**：

- 入口图标：组件 props 上**直接有 `sessionId`**，用它把「当前会话」传进请求。
- 面板页：**用 `useSessions` 推当前会话**（宿主自己两处就这么干），别用模块级变量 ——
  后者只在「必须由那个按钮打开」时成立，而面板还能从侧栏/快捷键进。

**成员 worktree 撞名**（§1 里那条副作用）：worktree 是**船长**用 `worktree_new` 建的、`squad_spawn`
只校验「盘上真存在」。所以这条落成**规矩 + 文档**：跨会话不要复用 worktree 名字，按
「会话/小队维度」取名。REQ 的验收只验「按这条规矩做，两棵确实是不同目录、都能跑命令」。

**CLI**：`squad ls` 的输出标明每条属于哪个会话；`--cwd` 的语义跟着改（或换成 `--session`）。

**两处待确认已由侦察解决**（`f284bf32`）：① store 不用改结构，换键即可；② 图标拿得到 sessionId，
面板用 `useSessions`。**没有遗留未知项。**

## 6. 天花板（做完之后仍不支持）

- 旧数据不迁移（见 §2）。
- 不做跨会话查看/管理别人的小队。
- 小队状态仍不跨**会话删除**保留：会话没了，它的落盘文件就成了孤儿（要不要清理另说）。
