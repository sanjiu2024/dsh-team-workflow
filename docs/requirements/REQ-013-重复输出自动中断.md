# REQ-013 · 重复思考/正文输出时自动中断

- **状态**：已完成
- **对应版本**：`1.17.0 → 1.18.0`（新增能力 → minor）
- **提出**：用户，2026-10-09，原话：「检测到模型在思考进入循环或者一直吐相同的几个字，自动中断对话」；后确认「1」= 只检测重复输出，不检测工具调用循环；阈值先选 **连续重复至少 8 字符的片段 4 次**，power 审查指出字面判定会误中断恰好重复的正常文本后，用户改为 **16 字符 × 4 次**。

---

## 1. 要做什么

模型在当前对话生成时，如果思考或正文连续重复同一个字面片段（至少 16 字符，连续出现 4 次），自动取消当前 turn，避免模型一直空转/刷屏。

- 思考（reasoning）与正文（text）分别检测；同一段跨多个 stream delta 时仍应能识别。
- 只检测**字面重复**，不做语义判断；完全相同的 8+ 字符片段连续出现 4 次即按用户选定阈值触发，即便极少数正常引用/示例也可能恰好符合该模式；不检测工具调用循环、相同工具调用或工具参数重复。
- 命中后用 Agent 的 turn 取消 API 中断当前生成；取消原因记录为 `hook`，明确说明检测到重复输出。
- 不改变未命中时的流内容、顺序或会话行为。

## 2. 为什么（不做的后果）

模型可能进入思考循环或反复输出相同内容，持续消耗 token 并阻塞对话；人工按停止键前会继续产生无效输出。

## 3. 不做什么

- 不检测同义改写/语义循环，只识别连续相同的字面片段。
- 不检测工具调用循环；工具调用不是这次用户确认的范围。
- 不自动重试、不删除已输出内容、不修改历史消息；只停止当前 turn。
- 不拦截其他 session 的流；通过 stream 请求里的 sessionId 只对所属 Agent 取消。
- 不允许依据 `session/event` 已完成消息来冒充实时检测；必须在实时 LLM stream delta 上检测。

## 4. 验收标准

- [x] 至少 16 字符的同一片段连续 4 次时，检测器命中；3 次不命中；15 字符片段不命中。
- [x] 检测跨多个 delta 边界；text 与 reasoning 各自独立，不能混合计数；tool-call delta 不参与。
- [x] 命中时仅取消同一 session 的当前 Agent turn，取消原因是 `hook`（`keepInbox:true`）；没有 live Agent 时安全放行流。
- [x] 未命中时所有 chunk 原样、同序传递；命中后不再继续向 agent-loop 传后续 chunks。
- [x] `npm test` 全绿；反向实验：`repeatPeriod()` 恒返回 0 → 专项自检变红（已还原）。
- [x] 用 fake stream + fake Agent 验证 `cancel` 被调用、AbortSignal 被 abort、命中 chunk 不下发；**未**在真 dsh 进程里端到端验证（本会话 `maxDepth 1`，且运行中的 dsh 早于本次改动）—— 只声称单测级验证。

## 6. 方案

新增纯逻辑模块 `lib/repeat-guard.js`，配置放入 `team/extensions/repeat-guard.json` 并由 `lib/index.js` 安装。安装器通过 Cordis 的 `llm/stream` waterfall 获取每次请求的流，只读请求 `sessionId`，每请求创建独立检测状态：按 `block-start` 的 block index 追踪 `text`/`reasoning` 类型，各类型各自维护最近 **512 个 UTF-16 code units** 的尾窗；其他 block 类型（尤其 tool-call）忽略。

每收到一段 text/reasoning delta，追加至其尾窗；在尾窗末端寻找周期 `p`，范围 `16..128` 字符，若末尾连续四个长度为 p 的片段逐字相同则命中。扫描只依赖最近尾窗，不留完整响应；不做 trim/大小写/标点归一，避免正常文本被宽泛归一后误中。不同 block、不同类型和不同请求绝不共享状态。命中时 `ctx.agents.get(options.sessionId).cancel({kind:"hook", reason:"检测到思考/正文重复输出（周期 N 字符，连续 4 次）"}, {keepInbox:true})`；不中断工具调用本身（但取消当前 Agent turn），不将命中后的 delta/yield给 agent loop。无 sessionId 或无活 Agent 时原样透传，不错误取消其他对话。

检测器纯函数返回命中的 period/类型，以便单测；中间件只负责转发、定位 Agent、取消与记录一次 warn。每个请求流结束后局部状态随作用域释放。配置仅有 `enabled`（默认 true）；固定阈值（16×4）是用户明确选定值，不另加未要求的调参面。

## 7. 天花板

- 只检测字面周期重复，不可能判断「措辞不同但语义循环」。
- **误中断**：正常内容恰好完全重复 16 字符 4 次也会被停（用户已按此权衡把阈值从 8 提到 16）；关掉用 `team/extensions/repeat-guard.json` 的 `enabled: false`。
- 重复输出已被 provider 产出、但尚未消费的少量 stream chunks 可能已不可撤回；检测后可阻止后续 chunks 进入 agent loop，并取消当前 turn。
- 没有活 Agent（如非 AgentLoop 的 hand-built LLM 请求）时不具备 turn 取消能力；不应误取消别的 session。
