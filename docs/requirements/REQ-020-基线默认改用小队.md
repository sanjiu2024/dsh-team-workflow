# REQ-020 · 基线默认改用小队开发

> **状态**：已完成 · **日期**：2026-10-16 · **版本**：`2.6.0`

## 1. 要做什么

把注入的团队基线（`team/RULES.md`）里「派活」那一节的**默认载体改成小队（Squad）**：
开发任务（要动代码、要多角色、要审）默认起队；子代理只留它做得到、小队做不到的几种窄场合。

用户原话：「怎么提示词里面是 subagent 而不是小队，建议使用小队进行开发」。

## 2. 为什么（不做的后果）

小队这套（REQ-009 / 015 / 016 / 017）是后加的，基线文本还停在子代理时代 —— 于是每个 agent
读到的是「派 `subagent_std`、先在 worktree 里干、绝对路径别写错」，而这三件事小队已经
**从「靠自觉」变成了工具层强制**：

- `worktree` 是 `squad_spawn` 的必填项，成员的文件操作被钉死在那棵树里，越界直接拒
- 共享黑板：进展/发现/结论写板上，主 agent 读板，不用当传声筒
- `squad_review`：把被审者的回报、worktree、验收清单塞进审查成员的 task

不改的后果：agent 继续用**没有隔离**的子代理写代码，继续踩「相对路径改到主仓库」的坑
（工具层面拦不住，只能靠嘴说），审查意见继续靠主会话转述。

## 3. 不做什么

- **不删**子代理那一节 —— 无工具的「判」（`subagent_power`）、`subagent_fork`、一问一答的窄活
  小队都做不到，删了就没法干活
- 不改任何工具实现、不改 `team/extensions/squad.json`、不改档位映射
- 不改「审查」那一节的两层语义（std 测 / power 判），只补一句「队里用 `squad_review`」
- 不引入新的强制：基线是提示词，不是闸

## 4. 验收标准（可执行）

1. `npm test` EXIT=0（`selftest.mjs` 钉的基线纪律句一条不少）
2. `team/RULES.md` 里有「默认载体是 Squad」与确切流程（`worktree_new` → `squad_new` →
   `squad_spawn` → `squad_review` → `worktree_merge` → `squad_close`）
3. 子代理那节仍在，且写清它**独占**的三种场合
4. 行数不涨：原第 78–266 行共 189 行，新版更短
5. 注入生效：`lib/baseline.js` 按 mtime 缓存 —— 改完**不用重启** dsh，下一次组装就是新文本
6. 实际用一次小队跑这件事的验收（见 §8）

## 5. 已知约束（查实的硬事实）

- 小队成员**都有工具**（`read` / `write` / `edit` / `grep` / `glob` / `bash` / `board`）→ 做不了
  「无工具的判」那一层，所以 `subagent_power` 必须留在子代理那节
- 成员不是 dsh 子代理：看不到本会话上下文 → 要 `subagent_fork` 的活只能子代理干
- `squad_review` 要求被审者**已收工**（审半成品只会得到半成品的结论）
- 状态落盘在 `<DSH_HOME>/team-workflow/squads/<工作目录>.json`，同一个工作目录开的新会话能捡回来
- `scripts/selftest.mjs` 钉了基线里几句纪律（派审查必须给边界 / 略过判据 / 单一真相源 /
  写计划前先派调研回来）—— 都在替换范围之外，但不能碰
- `scripts/usage-report.mjs` 有「见 `team/RULES.md` 的选档那节」的引用 → 「选档」这个节名要留着

## 6. 方案

替换 `team/RULES.md` 第 78–266 行（`## 子代理（subagent 工具）` 到 `## 上下文成本` 之前）为
`## 派活：开发用小队，窄活才用子代理`，结构：

三条硬理由（工具层隔离 / 黑板+落盘 / 审查入口）→ 确切流程 → 子代理的三种窄场合 →
回报必须短 → 选档（原内容保留，节名不变）→ `tier-max` 纪律 → 角色靠 prompt 声明。

## 7. 天花板（做完之后仍不支持）

- 基线只是提示词：agent 仍可以不看、或看了不用小队 —— 这一版不做强制
- 小队角色的档位仍由 `roles` 表定（审查是降级链），没有按任务难度自动升档
