# REQ-029 · 红队模式融合进团队模式

- **状态**：已完成
- **对应版本**：`2.11.0 → 2.12.0`（与 REQ-028 同批，加能力 → minor）
- **提出**：2026-10-31，用户原话「把红队模式融合进团队模式里面」

---

## 1. 要做什么

以前要单独切到「红队模式」（一份独立 agent 预设）才有 `redteam_*` 工具与红队指挥稿；
现在**团队模式本身就带红队能力**：一份预设、一套工具面、一份指挥稿。

## 2. 为什么

- 两种模式共用 `dsh-purge` 的同一套红队工具与事实库，只是 mode 下拉里的两个入口；
  用户切来切去，同一条任务要「先建会话选错模式 → 重开」。
- 红队指挥稿（运行环境前提 / 指挥职责 / 六角色 / 汇报口径 / 红线）**写了两份**：
  红队预设 persona 里一份、团队预设若要融合就得再抄一份。两份必然漂移。

## 3. 不做什么

- **不删红队模式预设**：「红队模式（窄）」留着 —— 它只带红队工具面，适合纯演练；
  团队模式是「工程 + 演练」全量。两者共用指挥稿与工具实现。
- 不把红队稿写进预设 persona：standard 底稿的 persona 是单行 YAML scalar，多行会被折叠，
  markdown 段落会糊成一行（这是改走插件层注入的直接原因）。
- 不合并 `squad`（工程小队）与红队五角色：两套并行，按任务选（写代码用 squad，演练用红队角色）。

## 4. 验收标准

- [x] 团队预设生成结果含 `- id: redteam-tools / name: dsh-team-workflow/purge/redteam/tools`
      → `node scripts/selftest-preset-gen.mjs`（rc.x 一节断言 `REDTEAM_ROW`）
- [x] 红队预设 persona 里不再有指挥稿 → 同上（`assert.ok(!g.text.includes("第一次开工前提醒用户一次"))`）
- [x] 指挥稿注入幂等、注释不进提示、改文件下一轮生效 → `node scripts/selftest-purge.mjs` ⑤
- [x] `npm test` 全绿（新增 `selftest-purge.mjs`）

## 5. 已知约束

| 约束 | 证据 | 影响 |
| --- | --- | --- |
| standard 底稿 persona 是单行 plain scalar | `lib/preset-gen.js:222` `RC2_PERSONA_PREFIX` | 多行稿只能走插件层注入，不能并进 persona |
| 一个包只有一个客户端入口 | `lib/client.js:5-6` | 红队面板与团队面板只能同文件 |
| 工具是 **preset 平面**的 | `presets/redteam/agent.cordis.yml` 的 `- id: redteam-tools` | 工具行必须进预设，插件层给不了工具 |

## 6. 方案

1. `team/REDTEAM.md`：指挥稿唯一真相源（HTML 注释包维护说明，注入前剥掉）。
2. `lib/redteam-brief.js`：systemPrompt 段 `team:redteam-brief`（order 660，按 host 幂等，mtime 缓存）。
3. `lib/preset-gen.js` 两个生成器加 `redteamTools`（默认 true）→ `patchAppend` 一行 insert。
4. `presets/redteam/agent.cordis.yml` 的 persona 稿换成一句说明。

## 7. 天花板

- 红队稿每轮都在系统提示里（约 11 KB 未压缩文本 → 约 3k token）。这是「融合」的直接代价；
  不想要就在 `team/extensions/redteam-brief.json` 里 `enabled: false`。
- 团队模式多挂一行工具（`redteam-tools`），工具定义也进每轮上下文。
