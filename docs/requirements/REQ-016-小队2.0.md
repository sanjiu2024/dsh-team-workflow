## 2. 为什么（不做的后果）

- **收不住**：一个成员跑飞只能连坐整队（A1）；烧 token 的唯一刹车是步数与 20 分钟墙钟（A2）；一次派 10 个就是 10 条 loop 同时打网关（A3）。
- **隔离是软的**：成员的 `bash` 沙箱档位取**宿主当前策略**，本会话是 `danger-full-access` —— 也就是说成员能写到 worktree 外面（A4）。这条一直没写进文档，用户以为有隔离。
- **协调全靠主 agent**：成员之间不能等、不能汇合（A6）；「每块产出必须有人审」只是系统提示里的规范，主 agent 忘了派就没人派（A7）。
- **重启就降级**：转录被压缩（B1）、`inbox`/`history` 不落盘（B2）、同 cwd 双进程互相覆盖（B5）。
- **看不见**：面板只有快照（B3）；命令行看不到小队（B6）；成本只有会话视角、成员调用算不进去（C1/C2）。
- **发版会漏**：13 个版本从没打过标签，就是没有守卫（D1）。

## 3. 不做什么

**用户这次没勾的（明确不做）**：

- **A5 成员嵌套** —— 成员不能再派成员，小队仍然只有一层
- **B4 面板写操作** —— 面板保持**只读**（加写路由要碰信任边界，没勾就不碰）
- **C3 价目表 / 算钱** —— 仍然只有 token，算不出钱（需要用户给单价）
- **D2 反向实验自动化** —— 反向实验继续手工跑（结果记进 §8）

**既有天花板不变**（REQ-015 §7 的继续有效）：

- 成员不能 `merge`/`drop` worktree、不能 `push`、不能改小队状态
- 成员不占 dsh 会话列表、成员的模型调用不算进会话账单
- 不引入**任何 npm 依赖**（零依赖是这个包的底线）
- 不做跨机器状态同步（B5 只解决本机跨进程）

## 5. 已知约束（侦察出来的硬事实）

> 三路调研（2026-10-16）：①dsh 插件实时推送能力 ②跨进程锁 + usage 数据源 ③19 项落点。
> 下面每条都是**查到的**，不是印象。

| 约束 | 证据 | 影响 |
| --- | --- | --- |

## 6. 方案

> 从 §5 的事实出发。**分五块**，块 1 是其余所有项的落点。

### 块 1 · 配置底座（E1 + D3）—— 已实现

- 新增 `lib/squad-config.js`：`SQUAD_CONFIG_VERSION`、`SQUAD_CONFIG_GROUPS`、`flattenSquadConfig(raw, warn)`
  （**纯函数**，把 v1 扁平 / v2 分组 / 两者混着压成一层）。
- `readJsonConfig` 加**可选** `normalize` 参数（`lib/util.js`），`layered` 透传（`lib/index.js`），
  **只有 squad** 那一行传 —— 不做全局钩子（§5 那条）。
- `team/extensions/squad.json` 升 v2：`configVersion: 2` + `defaults{provider,model}` +
  `limits{maxSteps,retries,memberTimeoutMinutes}` + `sandbox{bash}` + `roles{...}`。
- **为什么不写回文件**：包目录可能只读；运行时改用户的源码文件是意外行为。v1 照常读进来，只在日志提示一次。
- **D3**：`roleModel(roles, role)` 纯函数（查表前把尾部「型」去掉 —— 否则「审查」与「审查型」落到两条路上）；
  `squad_spawn` 不传 `model` 时按角色取；成员把**实际用的档位**记在自己身上（`model`/`provider`），
  落盘/还原/快照都带上，`squad_send` 续聊沿用 —— 否则「审查型配了 tier-power，续聊掉回 tier-std」没人查得出来。

### 块 2 · 可控性（A1/A2/A3/A4）

- **A1 `squad_stop`**：按人掐（复用 `abortMembers` 的单成员掐法 `lib/squad.js:838`），掐完自己写
  `status`/`note` 再落盘 —— `running` 是运行时字段、不进快照（`:263`）。
- **A2 预算**：`limits.tokenBudget`（0 = 不限）。**在步边界判**（只在收工判的话一步就能超），
  队级预算跨成员累加；超了走 loop 已有的 `max-tokens` 收工路径（`lib/squad-loop.js:216`）。
- **A3 并发**：`limits.maxRunning`（0 = 不限）。补位**挂成员 promise 的 `finally`** ——
  挂 `then` 的话异常路径不补位，队列永久堵死。
- **A4 角色白名单**：`sandbox.roleTools`（角色 → 允许的工具名）。**三处同时卡**：`schemas`、
  `executeTool` 的 allowed、系统提示里的 toolNames（漏一处 = 说给不到其实能调）。

### 块 3 · 协作（A6/A7/A8/A9/A10）

- **A6 等待**：**不做阻塞等待**（成员侧阻塞会死锁）。改成**事件驱动续跑**：成员以「等 X」收工，
  X 收工时把它叫回来（`startMember({resume})` 已有）；等待也有超时兜底，不许永久挂住。
- **A7 `squad_review`**：审查成员是**独立循环**，读不到别人的 `transcript`（`:919`，内存态）——
  所以工具必须把被审产出（结论 + diff + 文件清单）**塞进它的 task**。
- **A8 结构化回报**：收工摘要固定格式（交付物 / 证据 / 没做的 / 卡点）；模型自报不可靠，要解析兜底。
- **A9 模板**：`templates`（角色+任务骨架）落**配置**，别硬编码进代码（否则改分工要发版）。
- **A10 验收清单**：小队级 `acceptance` 数组（可勾）；**`reviveSquad` 必须补默认值**，否则旧文件读回 undefined。

### 块 4 · 持久化与观测（B1/B2/B5/B6/C1/C2）

- **B1/B2 同批**：转录按成员落 `.log`（照 `lib/session-log.js:107` 的原子替换），`inbox`/`history` 落盘 ——
  **同时升 `SQUAD_STORE_VERSION` 并写迁移**（§5 那条硬卡）。
- **B5**：`wx` 锁文件 + pid/mtime 双判据 + 超时（§5 那条）。

## 7. 天花板（做完之后仍不支持的）

- **A6 不解决环**：A 等 B、B 等 A 这种环不支持（会有环检测/超时兜底，但环本身不是合法用法）
- **B5 是建议性锁**：lockfile 不是内核强制锁；进程被 SIGKILL 后靠陈锁检测恢复，存在极小窗口
- **成本只覆盖本机**：另一台机器的会话不进来；小队成员的调用能不能算进去取决于 B1/B2 落盘的 usage 完整度
- **B3 依赖宿主**：若宿主没有流式能力，退化为更高频轮询（不是真推送）
- **配置 v2 只向后兼容读**：v1 能读进来，但不做 v2 → v1 的降级写回
- **A4 不是真沙箱**：工具白名单 + 策略开关能收窄成员的能做的事，但**最终强度仍由宿主策略决定**（这条要写进 REQ-015 §7）
