# REQ-022 · 完整适配 dsh 0.2.1-rc.2：`toolFilter` / `persona` 已废弃，改用 `agentPreset`

> 状态：已完成 · 提出：2026-10-18（用户原话「你完整把工作流适配0.2.1-rc2，并且你自己想办法测试」）

- **状态**：已完成
- **对应版本**：`2.6.2 → 2.6.3`（只修 bug → patch）
- **提出**：升级到 0.2.1-rc.2 后**新建会话直接失败**，报错原文：
  `agent-preset/invalid: tool-subagent-power (@deepseek-ai/dsh-tool-subagent): tool-subagent: toolFilter is no longer supported; configure persona and tool plugins in an Agent Preset and select it with agentPreset (spawn only)`

---

## 1. 要做什么

让团队预设**在 0.2.1-rc.2 上合法**。0.2.1 把 `tool-subagent` 的 `toolFilter` 与 `persona` 两个配置字段**废弃**了，
而团队预设的三条档位工具行里正带着 `toolFilter`（那是 REQ-012「审查档不给工具」的实现方式）——
于是整份预设被判非法，**新会话建不起来**。

要的结果：档位工具行用 0.2.1 认可的方式表达「这一档没有工具」，并且**有能自己跑的测试**证明这一点。

## 2. 为什么（不做的后果）

- **新会话完全不可用**（`新建会话失败：agent-preset/invalid`）—— 这不是"卡片显示红了"，
  是功能坏了。当前这个会话能干活只是因为它是升级前建的。
- 团队规范里「审查档凭材料判断、不给工具」这条设计**依赖**该能力：没有它，power 档就能
  自己探索仓库（上游实测最慢一次 108 轮、跑满 30 分钟被砍）。

## 3. 不做什么

- **不改 `tier-std` / `tier-max`**：它们带工具是设计意图（跑测试 / 质疑方案要能自己看）。
- **不改 REQ-012 那份历史文档**：它记录的是当时的机制，历史就是历史；改的是**活文档**
  （`team/RULES.md` 的基线文本、`README.md`）。
- **不动 fold 压缩后端**：它在 0.2.1 上没问题（之前那次"fold 挂了"是误判 —— 真正的原因就是本节这条）。

## 4. 验收标准

- [ ] 生成出的预设里 `toolFilter` / `persona`（作为 `tool-subagent` 的配置键）**零处**
- [ ] power 档那条行带 `agentPreset: team-power`，且 `team-power` 这个预设**存在**
- [ ] `team-power` 预设的 `plugins` 里**没有任何 `tool-*` / `skill-*` / `command-*` 行**（无工具）
- [ ] 自检新增断言，且**反向验证**：把生成器里的 `agentPreset` 改回 `toolFilter` → 自检必须变红
- [ ] **真宿主测试**：用真 cordis + 宿主自己的 `@deepseek-ai/dsh-tool-subagent` 挂载那条行 →
      旧写法**必须失败**、新写法**必须挂上**（这条是"自己能测"的核心）
- [ ] headless 冒烟：带新预设起一个 headless profile → `preset-team` 激活、无 `agent-preset/invalid`
- [ ] 全仓自检失败数不超过升级前那 4 条
- [ ] `package.json` = `CHANGELOG.md` 首个标题

## 5. 已知约束（查实的硬事实）

| 约束 | 证据 | 影响 |
| --- | --- | --- |
| `toolFilter` 与 `persona` 在 0.2.1 被**运行期**拒绝 | 宿主 `dsh-tool-subagent/lib/index.js:355`：`for (const field of ["persona","toolFilter"]) if (Object.hasOwn(config, field)) throw new Error(...)` | 必须彻底不写这两个键 |
| 替代机制是 `agentPreset` / `allowedAgentPresets` | 同文件 `:321-322` 的 `Config`；`:201-252` 的 `SubagentPresetSelection`；`:243` 要求 provider 支持 `agentPreset` 且不继承父上下文（"spawn only"） | 档位行用 `provider: spawn`，天然满足 |
| **`Config` schema 不拦这两个键** | 实测把 `toolFilter`/`persona`/`backgroundMode`/`inject` 全喂给 `Config` → **全部通过** | 拿 schema 验**测不到**这个 bug，必须真挂载 |
| 校验发生在**挂载期**，且在 web-app 的 preset realm 里才触发 | 同一个预设：headless（无 web-app）能挂 ✓，桌面（有 web-app）报 `agent-preset/invalid` ✗ | 我原来的 headless 手段**咬不住**这个 bug，测试要另做 |
| `preset` 可以有多条，各自 `id`/`order` 不同 | 出厂同时有 `preset-standard`(order 1) / `preset-ptc` / `preset-minimal`(order 3) | 无工具档位用**独立的子预设**承载 |
| 子预设可以极简 | 出厂 `minimal.patch.yml` 就是一份独立预设（persona + 被阉割的 tool-fs + compaction 组） | 无工具档位只需 persona + agent-instructions + compaction 组 |

## 6. 方案

1. `lib/preset-gen.js`：
   - 删掉 `toolFilter: allow: []` 的生成（`:382`）。
   - `toolLessTiers` 里的档位改成写 `agentPreset: team-<tier>`。
   - 在生成的 patch **末尾追加一条新的 `- insert:`**，声明无工具子预设
     `team-<tier>`（persona + agent-instructions + compaction 组，**没有任何 tool/skill/command 行**）。
   - 追加的块同样进 `patches` 撤销链，保持「逐条撤回去必须逐字节等于出厂」这条自检成立。
2. `scripts/selftest-preset-gen.mjs`：把"power 行有 toolFilter"的断言换成
   "power 行有 agentPreset + 子预设存在 + 子预设无工具行"；补反向验证。
3. **新增 `scripts/smoke-preset-tier.mjs`**（不进 `npm test`，依赖本机 dsh 安装树）：
   用 Electron-as-node + `createRequire(<asar>)` 取出宿主**真的** `@deepseek-ai/dsh-tool-subagent`，
   用真 cordis 挂载档位行 —— 旧写法应失败、新写法应挂上。
4. 活文档：`team/RULES.md`（基线文本里那段 `toolFilter` 说明）、`README.md` 的档位表。

## 7. 天花板（做完之后仍不支持）

- 无工具档位靠"另开一个预设"实现，所以它**继承不到主预设的 persona 文本**（要单独写）。
- `agentPreset` 只对 `provider: spawn` 生效；换成会继承父上下文的 provider 就没法独立选预设。
