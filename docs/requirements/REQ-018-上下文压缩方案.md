## 1. 要做什么

**不换摘要算法**。做三个部件，顺序就是优先级：

1. **③ 取回通道（第一件做）**：会话原文本来就在 append-only JSONL 里，缺的是「取回它的通道」。
   做：按**区间/关键词**取回历史事件的工具 + 折叠时写下**事件区间指针**（「事件 #1201–#1480 已折叠，
   原文在 `<session>.jsonl>`，可用工具展开」）。可搜索、可展开、可逐字核对。
2. **② 出处过滤（第二件做，最便宜）**：压缩**之后**逐条判「这条摘要有没有环境输出支撑」——
   没有出处的删掉。**不改 agent、不改 compressor、不改提示词**（正好绕开 dsh「摘要提示词零配置面」
   这个死结）。
3. **① 确定性折叠（最后做，要换后端）**：折叠时**不叫模型写摘要**，机械地做两件事 ——
   **逐字保留**（user 消息、assistant 里明确做出承诺/决策的消息、被标记要保留的工具输出），
   其余**丢成墓碑 + 区间指针**。零 LLM、完全确定、随时可回滚。
   形状上必须是**选择性**折叠，不是「全留」（见 §6 里 lossless fold 不稳定的实测）。

### 怎么知道它有效（KPI，可测）

证据里唯一**动过**的指标不是完成率，而是**检索类工具调用次数**（见 §6）。所以 KPI 就定这三个：

| KPI | 怎么量 | 期望方向 |
| --- | --- | --- |
| 检索/展开调用次数 | 从成员转录与审计日志里数 | 上升（说明 agent 在主动取回，而不是猜） |
| 单位任务的 token 成本 | `dsh-team bill --date` 的 total 与 cacheRead | 下降 |
| 出处过滤命中数 | ② 的过滤器报出多少条无出处摘要 | 有命中（命中越多说明原来在编） |

## 2. 不做什么

- **不换摘要模型/后端去追「更好的压缩算法」**：没有任何 head-to-head 证明固定阈值下只换摘要算法
  有稳定收益；能取到的同条件对照反而说收益来自窗口外存储与取回（§6）。
- **不调 `thresholdRatio` / `retainRatio` 追完成率**：固定阈值下只改压缩强度，完成率**无显著变化**
  （§6）。做了也看不出来。
- **不做图/树记忆**（RAPTOR / HippoRAG / Zep / Mem0 / Letta）：都要嵌入模型或外部服务，
  落不进 dsh「一个 context 一个纯函数后端」的形状。
- **不做 KV 驱逐 / token 级压缩**（LLMLingua 那类）：宿主够不着 KV 层；token 压缩在 tool-calling
  上有实测的可靠性断崖。
- **不做「更聪明的选择策略」**（PACMS 类）：实测「随机选择 ≈ 离线事后 oracle」——
  选择策略本身的天花板就低，投入不值。
- **不改 dsh 的摘要提示词**：rc.x 里那是零配置面，改不动也不该改。

## 4. 已知约束（两轮调研查实的硬事实）

- **dsh 一个 context 只能挂一个压缩后端**：想换算法只能**替换**，不能叠加。所以 ① 必须排在最后
  （它是替换），③② 是叠加（可以随时回滚）。
- **摘要提示词 / checkpoint 格式零配置面**：`compaction-basic` 只认
  `thresholdRatio` / `headroomTokens` / `retainRatio`|`retainTokens` / `summarizationProvider+Model` /
  `maxTokens` / `compactionRetries` / `maxOverflowRetries` / `modelPolicies` / `auto`，
  **未知键直接抛错**（整个 dsh 起不来）。所以 ② 只能做成**后处理**。
- **原文一直在**：会话事件是 append-only JSONL（`dsh-session-persistence-jsonl`），
  所以 ③ 不是「新建存储」，是「补一条取回通道」。
- **magic-context 已经在做一半**：它折叠到 65%、dsh 70% 兜底，取回靠**系统提示注入**。
  ③ 要补的是「**可搜索 / 可展开**」那半 —— 注入是它给你什么你看什么。
- **当前生效值**（预设里）：`thresholdRatio: 0.7 / retainRatio: 0.05 / auto: true`；
  `contextWindow` / `reserveTokens` / `keepRecentTokens` **不是 dsh 的键**，只是本包推算比例的材料。

### ① 确定性折叠后端：方案（2026-10-16，动手前先写下来）

**要做什么**：一个**不调 LLM** 的压缩后端 —— 把待压缩区间做**确定性折叠**（逐字**选择**保留什么、
丢掉什么，不重写、不摘要），产物仍按宿主协议写成 checkpoint。

**为什么这么选**（不是偏好，是证据）：

- 「确定性 + 逐字 + 显式丢失标记」这一组，是压缩方案里唯一**不需要信任模型**的一类（arXiv 2610.20116）；
- 唯一一次同条件头对头（pi-fold，Zenodo 22142456，2026-08-28）：给了窗口外存储 + 取回通道之后，
  折叠与原生压缩**打平**，而折叠**成本只有一半**；
- 另一条实测（arXiv 2608.16370）：**改压缩强度不影响任务完成率**，随机选条目 ≈ 离线最优 ——
  也就是说「选得聪明」的边际收益很小，**「别丢原文、丢了要说清」**才是重点。

**缝：子类化 `BasicCompactionEngine`，只覆写 `summarize()`。** 不直接继承 `CompactionEngine` ——
那样配置校验（`thresholdRatio` / `headroomTokens` / `retainRatio`）、自动触发（`agent/pre-step`
压力 + `agent/request-error` overflow）、token 估算、写盘顺序与那几条不变量全都要自己再做一遍，
风险面大得多。覆写 `summarize()` 之后，**唯一变化的是摘要内容**，其余全继承。

**折叠算法**（确定性，输入相同 → 输出相同）：

1. 按事件类型分档：**用户消息逐字保留**（那是需求本身）；工具结果取**首尾**（head/tail，中段丢）；
   assistant 只留**结论行**（丢了要在标记里说明）；错误行、命令、路径一律保留。
2. **预算**：折叠产物必须**严格小于**被压内容 —— basic 自己有一道「摘要不比被压内容小就 throw」的闸
   （`dsh-compaction-basic/lib/index.js:600-601`）。所以按预算选，选到预算为止。
3. **显式丢失标记**：产物里写明丢了哪几类、丢了多少、原文怎么取回（指向 `session_recall`）。
   这是「透明压缩」的硬要求 —— 静默丢内容比不压缩更危险。

**开关**：`team/agent-settings.json` 加一个**不写进插件 config** 的键
（`compactionBackend: "basic" | "fold"`，默认 `basic`）；`lib/preset-gen.js` 按它生成 compactor 那一行；
`package.json` 的 `exports` 加子路径（包有 `exports` 映射，不加解析不到）；
`scripts/selftest-preset-gen.mjs` 为 fold 那一支加断言（现有断言钉的是 basic 的默认路径，别改坏）。

**验收标准**：① 套件（纯函数级 + 变异）；② `preset-gen` 生成物里后端名正确、默认仍是 basic；
③ **真实会话里压一次，宿主接受产物**（不变量不炸）—— 这条最重要，也最可能翻车。

### ② 的缝在哪（已查明，2026-10-16）

**第一版接线是错的，已撤。** 我原本把过滤挂在 `agent/pre-step`，靠它的 decision
`{kind:'enter', messages}` 替换消息 —— **在真实宿主里那是空操作**：`agent/pre-step` 只能替换
「inbox 里待入场的 `UserMessage`」，而模型侧的消息数组是 `dsh-agent-loop` 的 `deriveMessages()`
**现场从 surface 导出的，中间没有任何钩子**（`agent/request` 的类型注释明写 "cannot mutate
messages"；`llm/stream` 拿到的是 deep-frozen 请求）。checkpoint 是**已经落在 surface 上的节点**，
根本不经过 pre-step。

**正确的缝：`surfaceOp:{op:'replace'}` 原地换节点。** 先例是 `dsh-compaction-tool-result-pruner`
（`lib/index.js:139-177`），dsh 自己的压缩也走同一条路（`dsh-compaction-basic/lib/index.js:650`）：

```js
for (const seq of [...session.surface.nodes]) {
  const event = session.eventAt(seq);
  if (event?.type !== "user/message") continue;
  const original = session.deriveEventMessage(event);          // 模型侧消息
  const filtered = await 过滤(拼出纯文本(original));            // lib/context-filter.js 的纯函数
  if (filtered === text) continue;
  const message = freezeMessage({ ...original, content: [{ type: "text", text: filtered }] });
  session.append("user/message", message, {
    surfaceOp: { op: "replace", startSeq: seq, endSeq: seq },
    sourceEventSeqs: [seq],
  });
}
```

- 触发点要**两个**：`agent/pre-step`（常规）与 `agent/request-error`（overflow 重试不重跑 pre-step，
  `dsh-compaction-basic/lib/index.js:860`）。
- `freezeMessage` 可以直接 `import { freezeMessage } from "@deepseek-ai/dsh-llm"` —— pruner 就这么干。
- **做不到**的：删节点 / 减节点数（两种 `surfaceOp` 都保留节点）→ 所以只能「改写」不能「删除」。
  好在过滤本来就是改写内容，不改节点数。

**接线已按上面那条缝写完**（`2.3.0`）：`installContextFilter` 挂在 `agent/pre-step` 与
`agent/request-error` 两个 waterfall 上（都 `return next()`，钩子自己不抛），遍历
`session.surface.nodes` 把 checkpoint 节点原地换掉。**幂等**：换过的节点内容全部有出处 →
第二遍 `dropped === 0` → 不再 append。**做不到删节点**，所以是改写内容。

顺序理由：③ 是唯一被同条件实测证明「把两种机制都抬到上限」的变量；② 最便宜且直打已定位的失败模式；
① 是替换、风险与工程量最大，所以放最后，且做完要拿 ③ 兜底。

**从别处借来的两条**（不是选项，是配件）：OpenHands 的 **append-only 事件日志 + 墓碑事件 + `View`
投影层**骨架（与宿主 JSONL 同构）；Codex 的 **「不摘要、直接开新窗口」** 模式（零 LLM，可做 overflow
之外的逃生门）。

### ③ 的落地记录（2026-10-16，`2.2.0`）

侦察改掉了原来的草图 —— 三处**都是「别自己造」**：

| 原计划 | 实际 | 为什么改 |
| --- | --- | --- |
| 自己读会话 JSONL | 用宿主 `ctx.sessionQuery`（`readEvent`/`searchEvents`/`listEvents`） | `.jsonl.zstd` 是**多帧串联**，Node 的 zstd API 只解第一帧（实测 202KB 只出 281 字节）；宿主按后端解，不挑格式 |
| 地址用行号 / mc 的 ordinal | **`seq`**（会话内单调、从 0 连续） | 行号依赖文件布局；mc 的 ordinal 会随折叠漂移 |
| 让 mc 在折叠时注入「已折叠区间」 | 工具的**索引模式**直接从日志读 `shadowedSeqs` | mc 的 `compartments` 本机 0 行、`ctx_search` 报 `Could not resolve project identity` —— 挂上去等于依赖坏组件 |

工具三种用法：不带参数 = 索引（总数 / seq 区间 / **折叠过的区间**）；`{query}` = 关键词；
`{seq}` 或 `{from,to}` = 逐字原文（窗口 50，超预算明说）。失败**必须 throw**（返回「失败」文本会让
模型以为取到了东西）。工具描述本身就是发现机制（dsh 把工具描述给模型），所以不需要往系统提示里
塞一段注入 —— 少一处耦合、少一份常驻 token。

**没断言**：真实宿主里 `exec.agent.session.id` 的取值路径（套件用假 exec）—— 记在 `docs/状态.md` §4。

## 6. 证据（两轮调研，2026-10-16）

- **唯一真正的同条件对照**：[pi-fold: Rotation and Retention](https://zenodo.org/records/22142456)
  （2026-08-28，同一冻结 64 阶段任务，8 个 graded run）——native compaction **4/16**，且逐行审计证明
  **它的全部得分都能由它自己的摘要文本解释**；lossless fold（保留全部字节）**4 次跑出两个模式**；
  **把窗口外 canonical memory store 同时给两种机制后，compaction 被抬到共同上限（无错答），
  fold 追平且只花一半的钱**。
- **失败模式的定位**：[Prune the Summary, Not the History](https://arxiv.org/abs/2610.20927)
  （2026-10-14）——**83% 的失败 run 可追溯到执行了某条摘要条目，而多数条目没有任何环境输出支撑**；
  SJC（压缩后逐条判有无环境出处并删除）可靠性 **+2.1%~8.9%**，token 不增。
- **确定性优于摘要**：[transparent-compact](https://arxiv.org/abs/2610.20116)（2026-10-14）——
  确定性压缩 + 散文逐字不变 + 显式标注丢失位置，在承诺/事实召回上打平或更好，**尤其少「自信地胡说」**。
- **调参没用**：[2608.16370](https://arxiv.org/abs/2608.16370)（2026-08-17）——只改压缩强度，
  完成率**无显著变化**，但检索类工具调用 **6/6 模型-场景全升**（GPT-5.5：21.0→63.9，p=.002）；
  **随机选择 ≈ 离线事后 oracle**。
- **可借的实现**：OpenHands `software-agent-sdk`（append-only + `Condensation` 墓碑 + `View` 投影层，
  2026-10-17；注：`AmortizedForgettingCondenser` 已被移除）；Codex CLI（`compact_token_budget.rs`
  明写「skips model/server summarization and installs a fresh context window instead」、
  `new_context` 工具、`compact_retained_tool_outputs`）；Claude Code（把「清理旧工具结果」当成与压缩
  **并列**的独立机制）；Anthropic 的 structured note-taking 与 sub-agent（2025-09-29）。
- **明确不采用**：shedding-bench（自述 "no ranking, no construct validation"，无可用 head-to-head）；
  RAPTOR / HippoRAG / Mem0 / Zep / Letta（需嵌入服务）；PACMS（随机 ≈ oracle，上限低）；
  ACON（需离线蒸馏压缩指南 + 小模型）；FOCUS（training-free 且有效，但未见代码）。

## 7. 天花板

- ③ 只能取回**还在盘上**的东西；会话文件被清掉就没了。
- ② 的 judge 会误判（把有出处的判成没出处）→ 所以删除要留原文兜底、可回滚。
- ① 换后端是**替换**：换上去之后 dsh 原来的 checkpoint 格式不再产生（历史 checkpoint 仍可读）。
- 换算法本身**不会**让完成率变好（§6 第三条）—— 收益在成本、可回滚、少「自信地胡说」上。

### 实现过程中踩到并修掉的

- **`execute(args)` 里用 `arguments[1]` 拿 exec**：能用，但一改成箭头函数就静默拿到 `undefined`
