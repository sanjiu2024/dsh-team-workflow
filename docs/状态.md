## 1. 这是什么，现在能用到什么程度

`dsh-team-workflow`：给 dsh 加「团队工作流」的私有插件包 —— 零依赖、纯 ESM，
CLI 是 `bin/dsh-team.mjs`，以 symlink 装进 dsh profile 的 `node_modules` 下。
核心能力：小队（多成员并行、黑板、worktree 隔离、审查）、上下文节流（`thrift`）、
magic-context 记忆层、定时任务、成本账单。

## 2. 设计取舍（为什么这么设计，否决了哪些）

- **零运行时依赖、纯 ESM**。否决「引一个工具库省事」：这个包要装进别人的 dsh profile，
  多一个依赖就多一份版本冲突和供应链面。代价是自己写小工具（`lib/util.js`），
  接受。
- **magic-context 是 vendor 的 bundle，不是 cordis 插件**。否决「重写成插件」：
  它只读 SQLite（`~/.dsh/storages/memory/cortexkit/magic-context/context.db`），
  取回靠**系统提示注入**，不需要挂进 cordis 的服务图。代价是升级要手工同步上游。
- **小队状态机坚持「一个成员同一时刻只有一轮」**（`isRunning(member)` 是唯一判据）。
  否决「用 `status` 字符串判在跑」：2.0.2→2.0.9 这一串 P1 里有一半来自口径不一致
  （`squadView` / 面板 / 快照 / `squad_say` / `squad_send` / `squad_review` 各判各的）。
- **一轮成员循环独立成 `lib/squad-round.js`**（REQ-017 块 1）。原来挤在 2347 行的
  `lib/squad.js` 里，改一个收尾出口看不出另一个 —— 这是那批 P1 的**物理原因**。
  代价：21 个闭包依赖要显式注入，漏一个就 `undefined`（踩过 `LOOP_DEFAULTS`）。
- **「这一轮为什么结束」只留一个瞬时字段 `roundEnd`**（REQ-017 块 2）。否决
  「`stopNote` / `waitNote` 分开」：两个字段各清各的，2.0.6 的事故就是从这漏的 ——
  停一个「等待中」的成员时写的那句没人消费，留到了下一轮。
- **配置 v2 分组 + v1 向后兼容读**，但**不做 v2→v1 降级写回**：老配置能读进来，
  不往回写。否决「双向兼容」：只会让两套形状永远并存。
- **角色档位配成「降级链」而不是单档**（REQ-019）。否决「把默认换成本机有的那个档」：
  网关有没有某条渠道是**环境事实**，包这边查不到 —— 链对任何网关都成立，单档只对本机成立。
  代价是换档要看得见（写进成员结论栏），不然用户不知道这次是谁在跑。
- **取回通道走 dsh 自己的 `sessionQuery`，不挂 magic-context**（REQ-018 ③）。理由不是省事：
  mc 自己的 `ctx_search`/`ctx_expand` 走它自己的 SQLite 副本，而本机实测 `compartments` 表 **0 行**、
  `ctx_search` 直接报 `Could not resolve project identity` —— 挂上去等于让取回通道依赖一个已经坏掉的
  组件。地址用 **`seq`**（会话内单调），因为 mc 的 ordinal 会随折叠漂移。
- **压缩这件事的方向已定**（2026-10-16 调研，两轮）：**不换摘要算法**。
  唯一真正的同条件对照（[Zenodo 22142456](https://zenodo.org/records/22142456)）里，
  把「窗口外存储 + 取回通道」给两种机制之后，native compaction 被抬到共同上限、
  fold 追平且只花一半的钱；而只改压缩强度在**完成率上分辨不出来**
  （[2608.16370](https://arxiv.org/abs/2608.16370)）。定为
  **①确定性折叠（不叫模型）+ ②出处过滤 + ③取回通道**，待写成 REQ-018。

## 3. 天花板（能力边界，写清楚免得被当成 bug）

- **两个实例同 cwd**：小队落盘是**整份替换**（跨进程锁只保证「不同时写」，不做合并）——
  后写者会抹掉前者那批小队。
- **2.0.1 及更早落的不带队名 `.log` 不再被认**：升级后老会话只剩 JSON 里那 100 条摘要。
  试过兜底，两轮独立测各逮到一类串队（同名 / 消毒后同名 / 主人已不在 JSON 里）——
  根因是那个文件**没有归属信息**，所以宁可丢全文也不串队。
- **小队状态在进程内存里**（同时落盘）：别的进程读不到，跨进程只能看面板或落盘文件；
  dsh 重启后要**同一个工作目录**的新会话才能把小队捡回来（接管）。
- **环不支持**：A 等 B、B 等 A 这种环不是合法用法（有环检测/超时兜底，但不解决环）。
- **lockfile 是建议性锁**，不是内核强制锁；SIGKILL 后靠陈锁检测恢复，存在极小窗口。
- **成本只覆盖本机**：另一台机器的会话不进来；成员调用算不算得进去，取决于落盘 usage 的完整度。
- **成员的工具白名单不是真沙箱**：能收窄成员能做的事，**最终强度仍由宿主策略决定**
  （本机当前是 `danger-full-access`，dsh 在那一档直接跳过 confine）。
- **dsh 的压缩摘要提示词/checkpoint 格式零配置面**：未知键直接抛错，
  所以「压缩后过滤」（SJC 式出处过滤）只能做成**后处理**，不能改提示词。
- **`tier-power` 在本机网关侧没有可用渠道** → 调它报 503。所以「power 判」这一层
  目前跑不成（`roles.审查` 指向它，见 §5）。
- **一个 context 只能挂一个压缩后端**：想换算法只能**替换**，不能叠加。

## 4. 修了但没断言（诚实覆盖记录）

> 这些地方**代码是改了的**，但我的自检**咬不住**。不当成已验收。

- `.catch` 的轮次身份护栏 —— 独立测判定**不可达**（真实时序里进不去）。
- `requestWait` 的轮次守卫、`squad_say` 的排队判定 —— **我的套件构造不到那个时序**
  （旧轮的工具调用在步边界就被掐掉）。只有第七轮探针的证据。
- `roundEnd.kind` 判据 —— 试过「去掉 kind 只看 reason」，全绿：能走到收尾分支的
  `waiting` 状态在真实时序里不可达（`squad_stop` 会连 `waitingFor` 一起清）。
  留着是因为代价为零且语义清楚。
- 反向实验的**验证脚本本身也会骗人**：`run_mut` 的匹配串一度误传 `x`，
  四条「咬住」全是假的。教训是**先验验证器**（改用断言原文重跑才算数）。
- **取回通道的「与 JSONL 逐字一致」「区间无空洞」两条**（REQ-018 §3#1#2）：需要真实宿主，
  套件全程假 engine。**待做一次手工冒烟**（真实会话里压缩后调 `session_recall`，与
  `readSessionLog` 的原文逐字比）。
- **真实宿主里 `exec.agent.session.id` 这条取值路径**（REQ-018 ③）：套件用的是假 exec，
  所以「工具能从执行上下文拿到会话 id」只有类型定义与侦察结论支撑，没有行为断言。
- `.catch` 路径上的换档记录（REQ-019）：变异「删掉它」套件**全绿** —— 要咬住得让轮内抛错走到
  `.catch`，目前构造不到那个时序。
- `lib/squad-round.js` 里 `squad.closed` 那条分支（`closedDetail`）—— 所有调用点都有前置
  closed 守卫，所以它今天不可达，修完之后仍然只有**静态证据**（`deps` 里注了、函数存在），
  没有行为断言。
- **出处过滤的接线**（REQ-018 ②）：`lib/context-filter.js` 的纯函数有断言，但**接线还没写**
  （第一版接在 `agent/pre-step` 上，已查明是空操作、已撤）。所以这个功能**现在不生效**，
  一个字节都不改上下文。
- **假替身会把「没接上的缝」演成对的**（REQ-018 ② 的第一版）：套件用假 ctx 演了一遍
  `pre-step → 替换 messages`，全绿 —— 而真实宿主根本没有那条路（模型侧数组由 `deriveMessages()`
  现场导出）。所以「假替身照 `.d.ts` 造」只保证**字段对**，保证不了**缝对**：
  缝的可行性只能靠**读宿主的调用链**（或真实宿主里跑一次）来确认。
- 独立测还实测出两条**曾经是空断言**的地方（`requestWait` 写 `roundEnd`、等待分支清 `roundEnd`）——
  现在补了断言、变异各自变红，所以从这份清单里**移出**了。

## 5. 已知问题 / 下一步

#### 已知问题（未修）

1. ~~`roles.审查` 指向 `tier-power` 而本机网关无该渠道 → 派审查成员报 503。~~
   **已修（`2.1.0`，REQ-019）**：`roles` 的值可以是降级链 `["tier-power","tier-std"]`，
   主档用不了自动换档并把换档写进结论。剩下的边界：链只在**同一 provider 内**换档，

   `~/.config/cortexkit/magic-context.jsonc` 里写着「为什么必须压到 20%」，
   而值是 65 / 0.15 —— 说明停在旧时代。要修的是注释来源（模板），不是写入逻辑。
3. `team/extensions/scheduler.json` 的 `enabled: true` 是**本机开关**，故意不提交 ——
   别人拉下来是关的，别当成 bug。

   「真 git：并发检查不会互相踩」上失败，报「本地修改将被合并操作覆盖」；单跑 3/3 全绿、
   紧接着的全量又 `EXIT=0` —— 是链上并发时的 git 竞争。会动摇「EXIT=0 才算过」这条判据，
